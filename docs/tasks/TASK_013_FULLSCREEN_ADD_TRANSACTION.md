# TASK_013 — Полноэкранное добавление операции

- **Номер:** TASK_013
- **Название:** Fullscreen Add Transaction
- **Статус:** DONE

- `git status` (обнаружено, не вызвано этой задачей): рабочее дерево уже

## Цель

Убрать промежуточную нижнюю шторку «Добавить» (Расход/Доход/Перевод/Чек),
открывающуюся по центральной кнопке «+». Кнопка «+» должна сразу открывать
отдельную полноэкранную страницу создания операции с типом «Расход» по
умолчанию и переключателем типов (Доход/Расход/Перевод) внутри страницы.

## Границы работы

- Разрешено: `index.html` (разметка/стили/скрипты шторки `#addMenu` и
  формы `#overlay`/`.sheet`, обработчик `#addBtn`), новый файл
  `js/services/tx_form_service.js`, `sw.js` (регистрация нового файла в
  `ASSETS`, версия кэша), новый тест `tests/tx_form_service.test.js`,
  документация задачи/статуса/roadmap/changelog.
- Запрещено: менять бизнес-логику сохранения операций (`saveTx`, работа с
  `state.tx`/`AF.Store`), логику категорий/счетов/валют, другие экраны и
  шторки, не относящиеся к добавлению/редактированию операции,
  `.claude/launch.json`, `icon.svg`.

## Требования (сжато, полный список — в исходном запросе пользователя)

1. Тип по умолчанию при открытии — «Расход».
2. Переключатель Доход/Расход/Перевод в верхней части страницы, переключение
   без закрытия страницы.
3. Полноэкранная страница: safe-area, непрозрачный фон, вся высота, без
   вида bottom sheet, без шторки поверх формы; нижняя навигация не видна.
4. Кнопка закрытия/назад в шапке — возврат на экран, с которого открыли.
5. Системный back / свайп назад / программное закрытие — не оставляют
   приложение в неправильном состоянии.
6. Существующая бизнес-логика (доход/расход/перевод, категория, счёт,
   сумма, дата, заметка, повтор) — без изменений.
7. При переключении типа — только соответствующие полю.
8. После успешного сохранения — запись, обновление данных, закрытие,
   возврат на предыдущий экран (уже существующее поведение `saveTx`).
9. «Чек» больше не отдельный пункт стартовой шторки — функциональность
   (прикрепление фото чека) остаётся доступной внутри формы расхода/дохода.
10. Дизайн-система проекта без редизайна остальных экранов.
11. Тесты (в рамках архитектуры проекта — чистые Node-тесты для
    выделяемой логики) + ручная проверка Safari/установленного PWA.

## Критерии готовности

- По тапу «+» открывается полноэкранная страница с типом «Расход» сразу,
  без промежуточной шторки; `#addMenu` удалена.
- Переключение типа работает внутри страницы, показывает верные поля.
- Страница визуально полноэкранная (safe-area сверху/снизу, непрозрачный
  фон, без плавающей нижней навигации) в Safari и в установленном PWA.
- Закрытие (крестик, системный back, свайп, после сохранения) возвращает
  на исходный экран корректно, без сломанного состояния истории.
- Функция прикрепления чека доступна и работает из формы расхода/дохода.
- `node tests/tx_form_service.test.js` — зелёный.
- `git diff`/`git status` подтверждают, что изменены только файлы задачи.

## Что фактически сделано

1. **Убрана промежуточная шторка «Добавить»** (`#addMenu`) целиком — HTML-блок,
   CSS (`.add-menu`/`.am-item`/`.am-ic`) и JS-обработчики
   (`#addBtn`/`#addMenuClose`/click-outside/`.am-item` forEach) удалены.
   `#addBtn` теперь напрямую вызывает `openSheet(null)`.
2. **`#overlay`/`.sheet` (форма операции) переоформлена в полноэкранную
   страницу** — переиспользован уже существующий в проекте паттерн
   full-page overlay (`align-items:flex-start` на `.overlay` +
   `height:100%;border-radius:0` на содержимом, как у `#allTxOverlay`,
   `#catMgrOverlay` и т.д.), но класс `.sheet` **не переименован** в
   `.detail-sheet` — на него завязаны существующие `$('.sheet')` в
   `openKeypad()`/`closeKeypad()` (первый `.sheet` в документе); новое
   правило `#overlay .sheet{height:100%;max-height:100vh;border-radius:0;
   animation:fade .2s}` применяется поверх базового `.sheet` только к этому
   элементу. Safe-area сверху/снизу — уже существовавший padding
   `.sheet` (`calc(16px + env(safe-area-inset-top/bottom))`), не менялся.
3. **Шапка страницы**: drag-хэндл (`.grab`, не нужен вне bottom sheet) и
   плавающая круглая «×» заменены на `.detail-top` (тот же компонент, что
   у остальных полноэкранных страниц) с заголовком (`#txSheetTitle`:
   «Новая операция» / «Редактировать операцию») и `.iconbtn`-кнопкой
   закрытия (`id` сохранён — `#closeSheet`, обработчик не менялся).
   Переключатель Расход/Доход/Перевод (`.seg`) остался сразу под шапкой,
   порядок пунктов не менялся (не часть постановки, несвязанный редизайн).
4. **Тип по умолчанию и видимость полей по типу** вынесены в новый чистый
   сервис `js/services/tx_form_service.js` (`AF.Services.TxForm`):
   `DEFAULT_TYPE='expense'`, `visibilityFor(type)`, `titleFor(isEdit)`.
   `openSheet()`/`setType()` в `index.html` делегируют туда вместо
   повторения условий `isT==='transfer'` в каждой строке — поведение не
   изменилось, только источник правды стал тестируемым без DOM.
5. **Функция чека сохранена без изменений** — `#receiptBlock`
   («📷 Прикрепить фото чека») уже был частью формы расхода/дохода и
   остаётся видимым (через `visibilityFor`); отдельного пункта «Чек» в
   шторке (шторка удалена) больше нет.
6. **Системный back / свайп назад / программное закрытие** —
   `openSheet()` делает `history.pushState({txSheet:true},'')` при
   открытии; `closeSheet()` (крестик, backdrop-клик, Escape, конец
   `saveTx()`/`delTx()`) вызывает `history.back()` вместо прямого
   скрытия; фактическое скрытие (`classList.remove('show')` +
   `closeKeypad()`) теперь происходит в новом обработчике
   `window.addEventListener('popstate', …)` — единая точка для всех
   путей закрытия, включая системный back/edge-swipe (тот же механизм).
   Бизнес-логика `saveTx()`/`delTx()`/`renderReceipt()`/категории/счета/
   валюты не тронуты.
7. `sw.js`: `js/services/tx_form_service.js` добавлен в `ASSETS`, версия
   кэша `finance-v153` → `finance-v154`.
8. Новый тест `tests/tx_form_service.test.js` (15 проверок): тип по
   умолчанию, валидность трёх типов (и невалидность «receipt»/пустого
   значения), одинаковая видимость полей у Расход/Доход, видимость полей
   у Перевод, заголовок создания/редактирования.

  требование к порядку; смена порядка не является частью функциональной
  постановки и не выполнялась, чтобы не делать несвязанный редизайн уже
  устоявшегося компонента.
