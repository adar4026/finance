# TASK_060 — Детализация расходов по местам трат (категория → место → операции)

**Статус:** DONE (опубликовано)

## Контекст

Пользователь (2026-09-30): в аналитике видны только главные категории
расходов. Нужно видеть структуру внутри категории — по магазинам, кафе,
сервисам, получателям (логика как в Alzex: «Продукты» → отдельная кольцевая
диаграмма по Mercadona, Lidl, кафе… → операции конкретного места), но в
текущем стеклянном стиле LexMoney, без копирования визуала Alzex.

## Исследование (до изменений)

- Операция уже имеет необязательное поле **`payee`** (TASK_015,
  `js/services/tx_meta_service.js`): «получатель/магазин», свободный текст
  ≤ 80 code points, принцип «пусто = ключа нет», нормализация в
  `AF.Store.migrate` (единая точка для старта / restore / импорта).
  `payee` уже:
  - сохраняется в резервной копии `.afb` и JSON-экспорте целиком
    (`backup_service` / `export_service.toJSON` сериализуют `tx` как есть);
  - выгружается в CSV / XLSX / XLS-отчёт (колонка «Контрагент», позиция 5);
  - импортируется из CSV (колонка «Контрагент» / payee / получатель /
    merchant…, `import_source_service`), входит в fingerprint дубликатов;
  - ищется поиском, показывается в строках операций.
- Структурная подкатегория `subcategoryId` → `state.subcats`
  (`{id,categoryId,name}`, сидированные «Супермаркет», «Рынок»…) — это
  типы трат, а не места; заранее создаются в меню категорий.
- `location` («📍 Место», TASK_015) — адрес/город, не магазин.
- Аналитика `#scrCharts`: кольцо по категориям (`renderAnaPie`), тап по
  категории → сразу список операций `#catTxOverlay` (`openCatTx`) со своим
  собственным периодом «Месяц/Год/Всё/Период», не связанным с периодом
  Аналитики.
- Период Аналитики — глобальный `period/anchor/customFrom/customTo`
  (`AF.Services.Period`, режимы День/Неделя/Месяц/Год/Период), стрелки —
  `shiftPeriod()`; прошлый период — `rangeBack(1)`.

**Решение по данным:** «Место / магазин» = существующее поле `payee`.
Оно точно соответствует смыслу, уже поддержано backup/restore/export/import,
поэтому **новое поле не добавляется, миграция и запись в пользовательские
данные не нужны** (резервная копия перед миграцией не требуется — миграции
нет). Существующая подкатегория участвует в детализации как запасное
значение: ключ места операции = `payee`, иначе имя подкатегории, иначе
«Без подкатегории».

## Цель

1. Форма расхода: поле «Место / магазин — необязательно» сразу после
   категории, с чипами ранее использованных мест **только этой категории**.
2. Аналитика: тап по расходной категории → экран детализации категории с
   отдельной кольцевой диаграммой по местам и точным списком.
3. Тап по месту → операции только этой категории и этого места за тот же
   период; «Без подкатегории» → операции категории без места.

## Требования

1. Детализация учитывает только `type==='expense'`, выбранную категорию,
   выбранный период, базовую валюту (`txBase`).
2. Сумма строк мест = сумма категории; сумма категорий = общий расход.
   Каждая операция попадает ровно в одну строку.
3. Сортировка по сумме по убыванию; строка: маркер цвета сегмента,
   название (перенос до 2 строк), сумма, доля %, число операций.
4. «Без подкатегории» — только при наличии таких операций.
5. Диаграмма: ≤ 8 сегментов; при большем числе мест — 7 крупнейших +
   «Остальные» (нейтральный цвет, маркеры этих строк — тот же цвет);
   в центре — название категории, сумма, число операций; пустое состояние
   без диаграммы.
6. Период — тот же, что в Аналитике, стрелки — `shiftPeriod()`;
   сравнение с прошлым периодом без «∞%».
7. Экран операций места: крошки «Категория › Место», группировка по дням
   с итогом дня, редактирование/удаление; «Назад» → детализация →
   Аналитика с тем же периодом.
8. Подсказки мест в форме — только из расходов выбранной категории,
   по частоте и свежести; выбор чипом, ручной ввод, очистка.

## Результат

### Что планировалось

Детализация расходной категории по местам трат (кольцо + точный список),
переход к операциям конкретного места с тем же периодом, поле «Место /
магазин» с подсказками внутри категории — без нового поля данных, если
подходящее уже есть.

### Что фактически реализовано

**Модель данных.** Использовано существующее поле операции `payee`
(TASK_015). Новое поле, миграция, `SCHEMA_VERSION`, ключи хранения — не
менялись; записей в пользовательские данные, требующих резервной копии,
нет. Ключ места операции (`AF.Services.PlaceBreakdown.placeKey`):
`payee` → иначе имя подкатегории (`subcategoryId` → `state.subcats`) →
иначе `''` («Без подкатегории»); сравнение регистронезависимое, пробелы
схлопываются, подпись — самое частое написание. Удалённая подкатегория →
«Без подкатегории» без ошибки.

**Сервис** `js/services/place_breakdown_service.js` (чистые функции, без
DOM/state/localStorage; сумма в базовой валюте — колбэком `txBase`):
`breakdown` (строки по убыванию суммы, доли, счётчики; `total` = Σ строк),
`segments` (≤ 8 сегментов: 7 крупнейших + «Остальные» `REST_COLOR`,
«Без подкатегории» — нейтральный `NONE_COLOR`, цвета строк = цвета
сегментов), `filter` (операции места / без места / все), `suggestions`
(payee только этой категории и типа, по частоте, затем по свежести),
`change` (`new` вместо «∞%»).

**Форма операции** (`index.html`): `#payeeRow` перенесён в новый
`#placeBlock` сразу после «Подкатегории»; подпись «Место / магазин —
необязательно», чипы `#placeStrip` (перенос по строкам, длинные названия
обрезаются внутри чипа), ручной ввод (placeholder «Или введите новое
место»), кнопка очистки `#payeeClear`; повторный тап по выбранному чипу —
очистка; при редактировании чип сохранённого места подсвечен. У дохода —
прежний «Получатель» без чипов, у перевода блок скрыт. Автодополнение
`updatePayeeAc()` теперь берёт варианты только из операций того же типа и
категории. Сохранение — прежний `applyTxMeta` («пусто = ключа нет»).

**Аналитика → детализация.** Тап по одиночной расходной категории в
`#catLegend` → `openCatDetail()` → `#catDetailOverlay`: «Назад», иконка и
название, период — общий `period/anchor` Аналитики (`periodLabel()`,
стрелки `shiftPeriod()`; для «Период» стрелки скрыты), кольцо
`#placeChart` (Chart.js doughnut, `spacing:2`, проценты на крупных
сегментах общим плагином `pieLabels`, названия — только в списке), центр:
название категории / сумма / «N операций»; сравнение с прошлым периодом
(`rangeBack(1)`): «Прошлый период: €X · ▲/▼ Y%», «без изменений», либо
«В прошлом периоде расходов не было»; список `.cd-row` (маркер, название
до 2 строк, доля · число операций, сумма); «Все операции категории»;
пустой период — карточка `#cdEmpty` без кольца (Chart уничтожается).
`render()` перерисовывает открытую детализацию (смена периода, CRUD).
Доходные категории и свёрнутый хвост «Другое» — прежний `openCatTx()`.

**Место → операции.** `openPlaceTx(catId,key,label)` открывает
существующий `#catTxOverlay` в режиме «по месту» (`catTxPlace`): крошки
`#catTxCrumb` «Расходы › Продукты › Mercadona», заголовок — место,
собственный выбор периода скрыт, период — тот же общий (стрелки двигают
его через `shiftPeriod()`), итог «Всего за …», группировка по дням с итогом
дня, строки с временем/местом/заметкой/счётом (`homeTxRow`),
редактирование и удаление через прежний `openSheet()`; для дня/недели
плитки «/мес» и «/год» скрыты. «Назад» → детализация (лежит под экраном,
уже с тем же периодом) → «Назад» → Аналитика. `openCatTx()` сбрасывает
режим (`catTxPlace=null`) — Бюджеты и доходы работают как прежде.
