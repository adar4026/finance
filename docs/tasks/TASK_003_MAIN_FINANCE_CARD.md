# TASK_003 — Main Finance Card

- **Номер:** TASK_003
- **Название:** Main Finance Card
- **Статус:** DONE

## Цель

Редизайн главной финансовой карточки на экране «Главная» (`#scrRecords`) по
референсу: белоснежная карточка с общим капиталом, кнопкой-глазом, изменением
за месяц, двухлинейным графиком накопленных доходов/расходов и тремя нижними
показателями (доходы/расходы/поток). Над карточкой — компактный переключатель
месяца стрелками.

## Текущее состояние (на момент начала, HEAD=885c0b6)

- `#scrRecords .capital` — фиолетовый градиентный блок (`--cap-grad`) с
  `wave-card.jpg` фоном, крупной суммой `#capVal`, тремя показателями снизу
  (`#capInc`/`#capExp`/`#capFlow`, реализовано в `.cap-bottom`/`.cib2`/`.ci2-*`
  — эти классы уже белые/нейтральные и переиспользуются без изменений).
  Изменения капитала за месяц нет вообще.
  Реального графика внутри карточки нет — только декоративный `.cap-wave` SVG.
- Переключение месяца для карточки отдельно не существует. Единственный
  существующий механизм — общий `.subhead` (`#periods` + `#navrow`,
  `period`/`anchor`/`shiftPeriod()`/`periodLabel()`/`inPeriod()`), который
  управляет одновременно: списком операций на Главной (`#recentList`),
  Аналитикой (`#scrCharts`) и принудительно месяцем на Бюджетах (`#scrBudgets`,
  `period` жёстко ставится в `'month'` при входе на экран, см. `showScreen()`).
  Этот механизм **не трогается** — используется отдельная, независимая
  переменная состояния только для новой карточки (см. «Архитектурное решение»).
- Приватный режим уже существует: `state.hideAmounts` (persisted в
  `AF.Store`/`localStorage`), кнопки `#capEye` (Главная) и `#capEye2` (Счета),
  функции `maskAmt()`/`fmtCur()`/`num()`/`updateEye()`. Переиспользуется
  существующий персистентный флаг; кнопка на новой карточке получает
  собственный независимый id (`#fcEye`), чтобы не трогать `#capEye2` на экране
  «Счета» (вне границ задачи).
- `AF.Services.Account.totalCapital(state, endDate)` уже умеет считать капитал
  на любую историческую дату (реплеем операций до `endDate`) — уже
  используется для спарклайна в drawer (`renderDrawerCap`) и для графика
  динамики капитала в Аналитике (`capPoints`).
- Chart.js 4.4.1 уже подключён (CDN, кэшируется `sw.js`) и уже используется
  для линейного графика с кастомным плагином конечного маркера+подписи
  (`capBubble`, см. `renderCapChart()` в Аналитике) — переиспользуется тот же
  паттерн для нового графика карточки вместо новой зависимости.

## Архитектурное решение: капитал за исторический месяц

Раздел 8 задания требует явно зафиксировать решение.

**Решение:** при переключении карточки на прошедший месяц показывается
**реальный капитал на конец этого месяца** (последний момент месяца), а не
текущий капитал. Для текущего (незавершённого) месяца используется капитал
**на данный момент** (`min(now, конец месяца)`).

**Обоснование:** `AF.Services.Account.totalCapital(state, endDate)` уже
поддерживает произвольный `endDate` и реплеит все операции до этой даты —
расчёт полностью надёжен для любого месяца (даже до создания счёта: тогда
используется `account.start`). Такой же приём уже используется в проекте
(`renderDrawerCap`, `capPoints`), поэтому это не новая, а переиспользуемая
модель. Изменение капитала за месяц = `totalCapital(конец месяца) −
totalCapital(момент перед началом месяца)` — математически совпадает с
(доходы − расходы) месяца, так как переводы между своими счетами не меняют
общий капитал.

## Архитектурное решение: карточка не переиспользует общий `.subhead`

**Решение:** карточка получает собственное, независимое состояние выбранного
месяца (`cardMonth`, локальная переменная), не связанное с глобальными
`period`/`anchor`. Список операций на Главной (`#recentList`), Аналитика и
Бюджеты продолжают работать от общего `period`/`anchor`/`.subhead` без единого
изменения.

**Обоснование:** общий `period`/`anchor` управляет тремя экранами одновременно
(Главная-список, Аналитика, Бюджеты). Если переиспользовать этот же механизм
для карточки (например, форсировать `period='month'` на Главной по аналогии с
Бюджетами) — новое требование «запрет перехода в будущий месяц» пришлось бы
вешать на общую `shiftPeriod()`, что задело бы Бюджеты и Аналитику — это прямо
запрещено границами задачи («не переделывать ... остальные экраны»). Отдельное
состояние — единственный вариант, гарантированно не затрагивающий Аналитику,
Бюджеты и существующий список операций.

### Расчёты (`js/services/finance_card_service.js`, новый файл)

Чистый модуль без обращений к DOM/localStorage — только `state` и переданные
callback'и (`txBaseFn`/`totalCapitalFn`), полностью юнит-тестируемый:

- `monthBounds`, `daysInMonth`, `addMonths`, `isFutureMonth`, `isSameMonth` —
  границы месяца по локальному времени (не UTC).
- `txForMonth` — операции месяца, переводы (`type==='transfer'`) исключены
  самой моделью данных (доходы/расходы и переводы — разные типы).
- `totals` — доходы/расходы/поток/количество операций месяца.
- `capitalAtMonthEnd`/`capitalChange` — капитал на конец месяца (или на
  текущий момент для незавершённого месяца) и изменение капитала за месяц с
  процентом (см. «Архитектурное решение» выше).
- `cumulativeSeries` — накопительные ряды доходов/расходов по календарным
  дням месяца с переносом значения в дни без операций.

### Главная карточка (`index.html`, инлайн-скрипт)

- `cardMonth` — собственная переменная состояния (не персистится, как и
  `anchor`/`period` до этой задачи — соответствует существующей UX-модели).
- `renderFinanceCard()` — считает месяц/капитал/изменение/показатели через
  сервис и вызывает `renderFcChart()`; подключена в общий `render()`
  (вызывается при каждом изменении данных: добавление/редактирование/
  удаление операции, счета и т.д.) и при первом `showScreen('scrRecords')`.
- `renderFcChart()` — линейный график на Chart.js (уже используемая
  зависимость, кэшируется `sw.js`; переиспользован приём с кастомным
  плагином конца линии, уже использованный в Аналитике для `capBubble`):
  доходы — сплошная зелёная линия с лёгкой заливкой; расходы — красная
  пунктирная (`borderDash`) без заливки; сетка — едва заметные горизонтальные
  линии; денежная шкала справа (`scales.y.position:'right'`); несколько
  дат по нижней оси (`autoSkip`, `maxTicksLimit`); плагин `fcEndMarkers`
  рисует цветные маркеры + компактные подписи итогов на концах обеих линий,
  автоматически размещая их выше/ниже точки, чтобы не перекрывались.
- Tooltip — кастомный Chart.js `external`-tooltip (`fcTooltipHandler`),
  рисует в собственный `#fcTooltip` (дата, доходы, расходы, разница),
  работает и мышью, и тапом (`interaction:{intersect:false,mode:'index'}`).
- Пустой месяц — `#fcEmptyMsg` показывает «Нет операций за месяц» поверх
  графика (реальный, не фиктивный ноль), высота карточки не меняется.
- Приватный режим — новая кнопка `#fcEye` (независимая от `#capEye2` на
  Счетах, но использует тот же `state.hideAmounts`): маскирует капитал,
  изменение, три показателя, подписи на графике и денежную шкалу (через
  `num()`/`fmtCur()`/`maskAmt()` — уже существующие функции), линии и даты
  остаются видимыми. `updateFcEye()` держит иконку/`aria-pressed` в
  синхроне; `#capEye2` (Счета) и `#swHide` (Настройки → Безопасность)
  дополнительно вызывают `updateFcEye()`, чтобы обе кнопки-глаза не
  расходились по виду при переключении с любого экрана.
- Анимация смены месяца — лёгкий fade+slide метки (`opacity`+`translateX`,
  ~160мс), пропускается при `prefers-reduced-motion: reduce`.
- Запрет будущего месяца — `FC.isFutureMonth(...)` дизейблит `#fcMonthNext`
  (`disabled` + `aria-disabled`) и блокирует обработчик клика.

### Найденные и исправленные во время проверки ошибки

- **Несовпадение сигнатур callback'а капитала**: `renderFinanceCard()`
  изначально передавал в `FC.capitalChange(...)` страничную обёртку
  `totalCapital(endDate)` (один аргумент, `state` захвачен через closure),
  а сервис вызывает её как `totalCapitalFn(state, endDate)` (два аргумента,
  сигнатура `AF.Services.Account.totalCapital`) — из-за этого `state`
  ошибочно передавался как `endDate`. Исправлено: на месте вызова передаётся
  `(s,endDate)=>AF.Services.Account.totalCapital(s,endDate)`.
- **Потеря `this` при передаче метода как значения**:
  `AF.Services.Account.totalCapital` внутри использует `this.active(state)`
  — при передаче как значения (даже с правильной сигнатурой) `this`
  терялся и вызов падал с `TypeError`. Исправлено той же обёрткой выше (вызов
  всегда идёт через `AF.Services.Account.totalCapital(...)`, с явным
  получателем).
- **CSS-специфичность `[hidden]`**: `.fc-empty{display:flex}` имело такую же
  специфичность, как встроенное `[hidden]{display:none}`, и как более
  «позднее» авторское правило перекрывало его — пустой месяц показывал
  «Нет операций за месяц» поверх карточки с реальными данными. Исправлено:
  атрибут `hidden` заменён на явный класс `.show`, переключаемый в JS
  (`classList.toggle('show', empty)`), без опоры на конкурирующую
  специфичность с `[hidden]`.
- **Отсутствовавший обработчик `#capEye`**: старый обработчик
  `$('#capEye').onclick=...` продолжал ссылаться на удалённый id и упал бы с
  `TypeError` при инициализации скрипта (обрывая все обработчики ниже по
  файлу). Переписан на `#fcEye`.

  - Пустой месяц (искусственно выбран январь 2020) — нулевые показатели,
    «Нет операций за месяц» поверх графика, без изменения высоты карточки.
  - Ширины 320px и 430px — без горизонтальной прокрутки
    (`scrollWidth===clientWidth`), без обрезки текста/бабблов.
  - Тёмная тема — карточка тёмная (не инверсия, отдельный `--card`/тени),
    контраст сохранён, без фиолетового градиента.
  - Экран «Аналитика» и «Счета» — визуально и функционально не изменились
    (фиолетовый градиент, `#capEye2`, графики — как раньше), без ошибок в
    консоли.
  - Добавление операции через форму (`saveTx()`) — операция сохраняется,
    карточка и список операций пересчитываются немедленно; тестовая
    операция удалена после проверки.
  - `prefers-reduced-motion: reduce` — программно подтверждено отсутствием
    инлайновой transition-анимации метки месяца при включённом флаге.
  - Ошибок в консоли не зафиксировано на любом из шагов
    (`read_console_messages`, включая `onlyErrors`).

## Известные ограничения

- Растяжение/сжатие маркеров и анимация метки месяца не проверялись на
  реальном iPhone/Safari в этой сессии — только в браузере предпросмотра;
  логика использует широко поддерживаемые стандартные API и деградирует
  безопасно (мгновенная смена без анимации) при `prefers-reduced-motion`
  или отсутствии поддержки.
- Переключение приватного режима и его персистентность проверены только
  вручную в браузере (не покрыты юнит-тестами, так как зависят от DOM и
  `localStorage`, а не от чистых функций сервиса).
