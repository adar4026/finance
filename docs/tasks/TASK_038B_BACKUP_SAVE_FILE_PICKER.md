## 1. Контекст

Точечный follow-up к `TASK_038` (буквенный суффикс — тот же приём, что
`TASK_038A`/`TASK_017A`/`TASK_003A`, номер `TASK_039` не занимает).
Сейчас по нажатию «Создать резервную копию» файл `.afb` формируется и
безусловно скачивается в папку загрузок браузера (`downloadFile()` →
`<a download>`). Пользователь просит дать возможность выбрать место
сохранения — в том числе iCloud Drive — через стандартный системный
диалог сохранения файла, если браузер и платформа это поддерживают.

## 2. Цель

При нажатии «Создать резервную копию»:

1. сформировать `.afb` как сейчас (без изменений
   `AF.Services.Backup.create()`);
2. если доступен `window.showSaveFilePicker` (File System Access API) —
   открыть системный диалог «Сохранить как» с предложенным именем
   `alex_finance_backup_YYYY-MM-DD.afb`, дать пользователю выбрать
   любую системную папку (включая iCloud Drive, если она примонтирована
   в системный file picker — сам picker выбирает ОС, приложение путь не
   хардкодит);
3. если API недоступен — сохранить обычное скачивание через `<a download>`
   (существующий fallback), результат для пользователя не меняется.

## 3. Границы

**Включено:**
- Обёртка `saveOrDownloadFile()` вокруг существующего `downloadFile()` —
  капабилити-детект `window.showSaveFilePicker`, запись через
  `FileSystemWritableFileStream`, откат на скачивание при отсутствии API
  или любой ошибке picker'а, кроме отмены пользователем.
- `doBackupCreate()` — использует новую обёртку; `state.lastBackup` и
  success-тост показываются только когда файл реально сохранён (не при
  отмене системного диалога пользователем).
- Минимальная блокировка повторного нажатия кнопки на время открытого
  диалога (`bkpBusy`), по аналогии с `expBusy`/`impBusy`/`rstBusy` из
  `TASK_038`.

**Явно исключено (не трогать):**
- Формат `.afb`, `AF.Services.Backup.create/inspect/migrateBackup`,
  checksum, envelope — не меняются ни на бит.
- Restore flow (`doRestoreCommit`, safety-копия перед восстановлением —
  её скачивание остаётся обычным `downloadFile()`: это автоматический
  внутренний шаг перед заменой данных, а не действие «Создать резервную
  копию», которое просит доработать пользователь; смена его UX не
  входит в эту задачу).
- CSV import/export, XLSX/CSV/PDF export, mapping, duplicate detector —
  не затронуты.
- Никакого backend/cloud storage, никакой прямой интеграции с Apple/iCloud
  API — выбор iCloud Drive выполняется исключительно пользователем через
  системный picker ОС.
- `SCHEMA_VERSION`, версия кэша `sw.js` — не меняются (изменений в списке
  кэшируемых файлов нет, новых файлов не добавлено).

## 4. Требования

- `showSaveFilePicker` вызывается синхронно от пользовательского жеста
  (клик по кнопке), без промежуточного `await` перед вызовом — иначе
  браузер теряет user activation и показывает `SecurityError`.
- Отмена системного диалога (`AbortError`) не считается ошибкой: не
  показывать `toastError`, не обновлять `state.lastBackup`, не показывать
  успех.
- Любая другая ошибка picker'а (например, `NotAllowedError` в
  ограниченном окружении) — тихий откат на обычное скачивание, не отказ
  пользователю.
- Содержимое файла, отданного через picker, побайтово совпадает с тем,
  что ушло бы через обычное скачивание — оба пути передают один и тот же
  `file` (строка от `AF.Services.Backup.create()`).
- Имя файла — `alex_finance_backup_YYYY-MM-DD.afb`, без изменений.

## 5. Критерии готовности

- Полный regression suite зелёный, без изменений тестов (логика
  сервисов не менялась).
- Проверено в браузере (в рамках возможностей текущего инструмента):

  - при замоканном picker'е (успех/отмена/ошибка) поведение соответствует

  - при отсутствующем picker'е — обычное скачивание работает как раньше;
  - файл, «сохранённый» через замоканный picker, проходит
    `AF.Services.Backup.inspect()` и восстанавливается.
- `git diff` — точечные изменения только вокруг `doBackupCreate`/новой
  обёртки в `index.html`.

## 6. Известное ограничение проверки

В используемом браузерном инструменте (headless/автоматизированный
Chromium) нативный OS-диалог «Сохранить как» нельзя ни увидеть, ни
провзаимодействовать с ним программно — это системный UI вне DOM.
Настоящую Safari/macOS в этой сессии тоже нельзя запустить (доступны
только Claude Browser и iOS Simulator, не desktop Safari). Поэтому:
- капабилити-детект и оба пути (picker/fallback) проверены через
  подмену `window.showSaveFilePicker` тестовым моком, воспроизводящим
  контракт настоящего API (`showSaveFilePicker → handle.createWritable →
  write → close`, включая `AbortError` при отмене);
- содержимое, переданное в `write()`, побайтово сверено с содержимым
  обычного скачивания и проверено через `Backup.inspect()`;
- реальное появление системного диалога и реальный выбор iCloud Drive
  пользователем в Safari/Chrome на его машине этой проверкой не
  покрывается и остаётся на ручную проверку пользователем.

стал `async`, использует обёртку, обновляет `state.lastBackup` и
показывает success-тост только при реальном сохранении (не при отмене
диалога). Добавлена блокировка повторного нажатия `bkpBusy` на время
открытого диалога/записи.

Тесты: **1581 passed, 0 failed** во всех 20 файлах `tests/*.test.js` —
без изменений (файл-логика в `index.html` не покрывается regex-сканером
`tests/reliable_save_screen.test.js`, а сервисы не менялись).

Проверено в браузере (`localhost:8912`, реальный Chromium — у него
`typeof window.showSaveFilePicker === 'function'`, поэтому picker
подменялся моком, воспроизводящим контракт настоящего API, во всех
сценариях, чтобы не блокировать автоматизацию реальным нативным диалогом):

1. **Picker доступен, пользователь сохраняет** — `showSaveFilePicker`
   вызван с `suggestedName: "alex_finance_backup_2026-08-19.afb"` и
   `types:[{accept:{"application/json":[".afb"]}}]`; в `write()` пришла
   строка; `Backup.inspect()` этой строки — `ok:true`, `counts.tx:1`;
   `state.lastBackup` обновлён, тост «Резервная копия создана ✓»,
   кнопка разблокирована.
2. **Пользователь отменяет диалог** (`AbortError`) — `localStorage`
   побайтово не изменился, тост не показан, кнопка разблокирована.
3. **Picker бросает иную ошибку** — тихий откат на `downloadFile()`:
   файл скачан с тем же именем, содержимое проходит `inspect()`,
   `lastBackup` обновлён, успех показан как обычно.
4. **Picker недоступен** (`delete window.showSaveFilePicker`) —
   поведение идентично тому, что было до `TASK_038B`: скачивание,

   `doBackupCreate()` не порождает второй вызов `showSaveFilePicker`
   (`pickerCalls: 1`), кнопка задизейблена всё время ожидания и
   разблокирована по завершении.

Консоль — без новых ошибок приложения (только фоновый CORS-шум
стороннего аналитического скрипта окружения, наблюдался и раньше).
