## Проблема

На iPhone/PWA верхняя шапка (`#topbar` — аватар/поиск/аналитика) при
overscroll/rubber-band (оттягивание страницы за верхнюю границу) сдвигалась
вниз вместе с остальным контентом, хотя формально использовала
`position:sticky;top:0`. Причина: прокручивался весь документ
(`body`/`html`, `.app` был обычным блоком в потоке без собственного
скролл-контейнера) — на WebKit/iOS элементы, закреплённые (`sticky`/
`fixed`) относительно скроллящегося документа, тоже визуально сдвигаются
во время эластичного оттягивания (elastic overscroll) всего документа,
поскольку смещается вся раскладка вьюпорта целиком, а не только его
внутреннее содержимое.

## Цель

Изолировать прокрутку: `html`/`body` перестают скроллиться вообще
(`position:fixed`, без возможности оттягивания), `.app` становится
нескроллящейся flex-рамкой на весь экран, а прокручивается только новая
внутренняя область `.scroll-area` (весь контент под шапкой — `.subhead` +
экраны `.screen`). Верхняя шапка при этом физически находится вне
скроллящегося контейнера и не может сдвинуться при рэббер-бэнде внутри
`.scroll-area`, независимо от версии iOS/WebKit.

## Границы работы

- Затронуть только: CSS-правила `html`, `body`, `.app`, новое правило
  `.scroll-area`; HTML-обёртку в `#scrRecords`'s родителе (обернуть
  `#subhead` и все `.screen` в новый `<div class="scroll-area"
  id="scrollArea">`); JS-обработчик `.topbar.scrolled` (сейчас слушает
  `window`/`scrollY`, должен слушать `#scrollArea`); два места
  автопрокрутки при drag-and-drop (`document.scrollingElement||
  document.documentElement` → `#scrollArea`) в `setupAccountSort`/
  `liftAccCard` (счета) и аналогичной функции для категорий (`liftCatCard`
  или её `move()`), т.к. они опираются на реальный скроллящийся элемент
  документа, который теперь меняется.
- Не менять: `.topbar` — визуальный CSS без изменений (тот же паттерн
  `position:sticky` + material-фон при `.scrolled`, но эффективно теперь
  всегда «над» независимой прокруткой, а не «внутри» неё); финансовую
  карточку, список операций (`TASK_004`), переключатель месяца
  (`TASK_005`), нижнюю навигацию (`.nav`, уже `position:fixed`, вне
  `.app`), все overlay/sheet/modal/drawer (уже `position:fixed`, вне
  `.app`, со своим внутренним `overflow-y:auto`) — их не трогать.
- Не менять safe-area отступы (`env(safe-area-inset-*)`) — используются
  как прежде в `.topbar` (верх) и в переносимом `padding-bottom`
  `.scroll-area` (низ, под плавающую `.nav`).
- Не менять бизнес-логику `render()`/`showScreen()`/фильтрацию/расчёты.

## Требования

1. Шапка (`#topbar`) не двигается при overscroll/rubber-band на любом
   экране (Главная/Аналитика/Счета/Бюджеты/Настройки).
2. Прокручивается только содержимое под шапкой; сама шапка всегда видна.
3. Нижняя навигация, safe-area, светлая/тёмная тема — без регрессий.
4. Существующая логика (переключение периодов/месяцев, drag-and-drop
   счетов и категорий с автопрокруткой у краёв экрана, collapsing-header
   material-эффект после начала прокрутки) продолжает работать.
5. Нет ошибок в консоли.

## Критерии готовности

- Визуально и через `touch`-эмуляцию: шапка неподвижна при pull-down/
  rubber-band, контент скроллится независимо, нет скачков/наложений.
- `#topbar.scrolled` появляется/исчезает при прокрутке `#scrollArea` как

- Drag-and-drop счетов/категорий с автопрокруткой у верхнего/нижнего края

  `#scrollArea`).
- Переключение вкладок нижней навигации, переключатель периодов/месяцев,
  финансовая карточка — без изменений в поведении.
- Нет ошибок в консоли.

## Фактический результат

### Реализация

- `index.html`:
  - CSS: `html{height:100%;overflow:hidden}`; `body` — вместо
    `min-height:100vh` теперь `position:fixed;inset:0;width:100%;
    height:100%;overflow:hidden` (классический паттерн полной блокировки
    прокрутки/rubber-band документа на iOS — `overflow:hidden` сам по себе
    на WebKit недостаточно надёжен, `position:fixed` исключает bounce
    полностью); `.app` — вместо `min-height:100vh;padding-bottom:...`
    теперь `height:100%;display:flex;flex-direction:column;overflow:hidden`
    (нескроллящаяся flex-рамка на весь экран); новое правило
    `.scroll-area{flex:1 1 auto;min-height:0;overflow-y:auto;
    -webkit-overflow-scrolling:touch;overscroll-behavior-y:contain;
    padding-bottom:calc(var(--navh) + env(safe-area-inset-bottom) + 26px)}`
    — `padding-bottom` перенесён сюда с `.app` (пространство под плавающую
    `.nav` теперь у скроллящегося контента, а не у нескроллящейся рамки).
    `.topbar` — CSS не менялся (тот же `position:sticky;top:0`), но
    физически теперь вне `.scroll-area`, поэтому не может сдвинуться при
    rubber-band внутри неё ни при каких обстоятельствах.
  - HTML: `#subhead` и все пять `.screen` (`#scrRecords`, `#scrCharts`,
    `#scrBudgets`, `#scrAccounts`, `#scrMore`) обёрнуты в новый
    `<div class="scroll-area" id="scrollArea">`, вставленный после
    закрывающего `</div>` `.topbar` и закрытый перед закрывающим `</div>`
    `.app`. `.nav` (нижняя навигация) и все `.overlay`/`.sheet`/`.modal`/
    `.drawer` остались снаружи `.app` без изменений (уже `position:fixed`
    со своим внутренним скроллом — не затронуты).
  - JS: слушатель `.topbar.scrolled` (материальный фон/тень после начала
    прокрутки) переключен с `window`/`scrollY` на `#scrollArea`/
    `scrollTop` — иначе он бы никогда не срабатывал (документ больше не
    скроллится). Два места автопрокрутки при drag-and-drop
    (`liftAccCard` — счета, `liftCatCard` — категории) переключены с
    `document.scrollingElement||document.documentElement` на
    `$('#scrollArea')||...` (с тем же фолбэком) — реальный скроллящийся
    элемент теперь `#scrollArea`, а не документ.
- `sw.js`: версия кэша поднята `finance-v146` → `finance-v147`.

### Известные ограничения

- Полноценный pointer-drag жест (перетаскивание карточки счёта/категории
