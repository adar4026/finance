# TASK_053 — Главная: тонкая текстовая шкала соотношения доходов/расходов

**Статус:** DONE (опубликовано)

## Контекст

На Главной под переключателем месяца стоит `.hero-balance#finCard` с тремя
показателями `.hb-stats` (Доходы / Расходы / Поток, `TASK_049`), сразу за
которыми идёт заголовок «Записи» (`index.html:2081-2089`). Расчёт сумм —
`renderFinanceCard()` → `AF.Services.FinanceCard.totals(state, from, to,
txBaseFn)` (`js/services/finance_card_service.js`), диапазон — общий
`AF.Services.Period`. Пользователь хочет добавить между этими блоками
компактный визуальный индикатор пропорции доходов/расходов — без чисел,
подписей и карточки.

## Цель

Сразу под `.hb-stats` (внутри `#finCard`, до заголовка «Записи») —
одна тонкая горизонтальная шкала (pill, 7–9 px высотой), без видимого
текста/цифр/процентов/легенды/заголовка/tooltip/карточки:

- зелёный сегмент слева — доля доходов (`var(--income)`);
- красный сегмент справа — доля расходов (`var(--expense)`);
- ширина сегментов = `income/(income+expense)` и `expense/(income+expense)`
  за текущий выбранный период (те же данные, что уже показаны в
  Доходы/Расходы/Поток — вторая независимая агрегация не создаётся);
- только доходы → полностью зелёная; только расходы → полностью красная;
  ни доходов, ни расходов → неброская нейтральная линия (`var(--line)`),
  без зелёного/красного;
- ширина шкалы — по ширине `.hero-balance`/`.hb-stats` (те же боковые
  отступы `#scrRecords{padding:8px 16px 20px}`), без своего контейнера/
  фона/рамки/тени;
- без вертикального «воздуха» — минимальный отступ сверху, не сдвигает
  «Записи» больше необходимого;
- динамический `aria-label` («Доходы NN%, расходы NN%») для screen reader,
  без видимого текста.

## Требования

1. `AF.Services.FinanceCard.ratio(totals)` — чистая функция:
   `{hasData, incomePct, expensePct, incomeLabelPct, expenseLabelPct}`,
   доли в процентах (0–100), `incomePct+expensePct===100` при
   `hasData===true`; при `income+expense<=0` → `hasData:false`,
   `incomePct:0, expensePct:0`.
2. `renderFinanceCard()` пишет `ratio(totals)` в ширины `#fcRatioInc`/
   `#fcRatioExp` (`style.width`) и в `aria-label` контейнера `#fcRatio`
   при каждом вызове (переключение периода/месяца, после CRUD операции —
   без дополнительных обработчиков, т.к. `renderFinanceCard()` уже
   вызывается из общего `render()`).
3. CSS: `.hb-ratio{height:7–9px;border-radius:999px;overflow:hidden;
   background:var(--line)}`, сегменты — `var(--income)`/`var(--expense)`,
   без бордера/тени/фона-карточки; отступ сверху — компактный
   (`margin-top`, без лишней вертикальной зоны).
4. Контейнер `#fcRatio` — `role="img"` + `aria-label`, без видимого
   текста; сегменты — `aria-hidden="true"`.
5. Light/dark — только существующие токены, контраст сохраняется без
   правок тем.
6. `sw.js`: версия кэша поднята.

## Результат

### Что реализовано

- **`js/services/finance_card_service.js` → `AF.Services.FinanceCard.ratio(totals)`.**
  Новый чистый метод, производная от уже посчитанного `totals()` — второй
  агрегации операций нет. `income = max(totals.income,0)`,
  `expense = max(totals.expense,0)`, `total = income+expense`. При
  `total<=0` → `{hasData:false, incomePct:0, expensePct:0,
  incomeLabelPct:0, expenseLabelPct:0}` (нейтральный случай). Иначе
  `incomePct=(income/total)*100`, `expensePct=100-incomePct` (не отдельное
  деление — гарантирует сумму ровно 100, без зазора в pill от
  плавающей точки). `incomeLabelPct=Math.round(incomePct)`,
  `expenseLabelPct=100-incomeLabelPct` — та же гарантия суммы для текста
  `aria-label` (пример из задачи: доходы €285/расходы €1 106,65 →
  `incomePct≈20.478`, `incomeLabelPct=20`, `expenseLabelPct=80` —
  «Доходы 20%, расходы 80%», как в примере постановки).
- **`index.html` → разметка.** Внутри `#finCard`, сразу после `.hb-stats`
  и перед закрытием `.hero-balance` (т.е. до заголовка «Записи», без
  промежуточных блоков) — `<div class="hb-ratio" id="fcRatio" role="img"
  aria-label="…"><div class="hb-ratio-inc" id="fcRatioInc"
  aria-hidden="true"></div><div class="hb-ratio-exp" id="fcRatioExp"
  aria-hidden="true"></div></div>`. Сегменты — пустые `div`, без текста;
  `role="img"`+`aria-label` на контейнере даёт screen reader одно
  осмысленное описание, сегменты `aria-hidden` не читаются отдельно.
  Ширина — та же, что у `.hero-balance`/`.hb-stats` (боковые отступы
  наследуются от `#scrRecords{padding:8px 16px 20px}`, свой контейнер не
  создавался).
- **CSS `.hb-ratio`/`.hb-ratio-inc`/`.hb-ratio-exp`.** `height:8px`
  (в диапазоне 7–9px), `border-radius:999px`, `overflow:hidden`,
  `background:var(--line)` (нейтральный фон — виден только когда оба
  сегмента нулевой ширины, т.е. `hasData:false`); сегменты —
  `background:var(--income)`/`var(--expense)`, без своего размера кроме
  `height:100%` (ширину пишет JS). `margin-top:8px`, без
  `margin-bottom`/`padding` — компактный отступ только сверху, «Записи»
  не сдвигается лишним воздухом. Никаких новых hex/rgba — только три
  существующих токена (`--line`/`--income`/`--expense`), в обеих темах
  уже согласованные (см. `index.html:64-68,133-136`).
- **`renderFinanceCard()`.** Три новые строки сразу после заполнения
  `#fcIncN`/`#fcExpN`/`#fcFlowN`, в том же проходе функции, до её конца:
  `const ratio=FC.ratio(totals)` → `$('#fcRatioInc').style.width=
  ratio.incomePct+'%'`, `$('#fcRatioExp').style.width=ratio.expensePct+
  '%'`, `$('#fcRatio').setAttribute('aria-label', ratio.hasData?
  \`Доходы ${ratio.incomeLabelPct}%, расходы ${ratio.expenseLabelPct}%\`:
  'Нет доходов и расходов за период')`. `totals`, `$('#fcInc')` и весь
  остальной расчёт (капитал/изменение/переключатель месяца) — не
  тронуты. Т.к. это тот же единственный проход `renderFinanceCard()`,
  который уже вызывается из общего `render()` при `shiftPeriod()`
  (День/Неделя/Месяц/Год/Период, смена месяца) и после каждого
  успешного CRUD операции — шкала синхронна со сводкой без отдельных
  обработчиков; подтверждено вручную в preview (переключение периода/
  месяца пересчитывает и цифры, и ширины сегментов одним вызовом).
- **`sw.js`** `finance-v184` → `finance-v185`.
- **Тесты.** Новый `tests/home_income_expense_ratio.test.js` (38
  проверок): место и состав разметки (после `.hb-stats`, до «Записи»,
  единственность `#fcRatio`/`#fcRatioInc`/`#fcRatioExp`), отсутствие
  видимого текста внутри шкалы, CSS (высота 7-9px, pill-скругление,
  `overflow:hidden`, отсутствие рамки/тени/blur, только существующие
  токены без hex/rgba, компактный отступ только сверху), точная запись
  `renderFinanceCard()` (`FC.ratio(totals)` из того же `totals`, запись
  ширин и `aria-label`, `#fcInc`/`#fcExp` не изменены), вызов `ratio()`
  в одном потоке с `#fcInc` (синхронность с `shiftPeriod()`/`render()`),
  версия кэша. Новый блок в `tests/finance_card_service.test.js` (10
  проверок): смешанный период (пример задачи, доли ≈20,5%/79,5%, сумма
  долей ровно 100, `incomeLabelPct=20`/`expenseLabelPct=80`), только
  доходы (100%/0%), только расходы (0%/100%), пустой период
  (`hasData:false`, обе доли 0), исключение переводов (через уже
  протестированный `totals()` — `ratio()` не видит трансферы, т.к.
  `totals.income`/`totals.expense` их уже не содержат). Две устаревшие
