# TASK_065 — Белая полоса над шапкой Главной (цвет системной области)

**Статус:** IN PROGRESS — выпущено как **v2.5.1** (cache `finance-v199`), опубликовано и
проверено на production. `DONE` **не ставится**: фактическое поведение статус-бара в
установленной PWA на iOS не подтверждено — нет устройства и Simulator, изменение проверено
только программно и в Dev Preview (см. «Что остаётся неподтверждённым»).

## Цель

Убрать белую полосу над голубым фоном Главной, не меняя геометрию вьюпорта, шапку, нижнюю
навигацию, отступы и палитру остальных элементов.

## Причина (доказана по коду и замерами)

Полоса — **не элемент страницы**. Замеры в превью: `.finance-ambient` (фон Главной) имеет
`top 0 … bottom 812`, то есть покрывает вьюпорт целиком; `html`, `body`, `.app` — тоже.
Внутри страницы закрашивать нечего.

Полоса — **системная область iOS** (статус-бар при
`apple-mobile-web-app-status-bar-style="default"`, введён в `TASK_011`). Её цвет задаёт не
страница, а мета-тег `theme-color`. И он был почти белым:

```
<meta name="theme-color" content="#f4f6fb" media="(prefers-color-scheme: light)">
```

`#f4f6fb` — практически белый, а фактический верх сцены Главной — голубой. Отсюда ровно тот
дефект, который видно: белая полоса над голубым градиентом.

Это же расхождение зафиксировано в `TASK_011` как отложенное:
`theme-color` переключался по **системной** `prefers-color-scheme`, тогда как тема приложения
живёт в `data-theme`/`localStorage`, плюс `manifest.theme_color` (`#0f1115`) противоречил
светлому мета-тегу.

## Почему выбран именно этот способ

| Вариант | Решение |
|---|---|
| `black-translucent` (фон под статус-бар) | **Отклонён.** `TASK_011` замерил на iPhone: вьюпорт 759 вместо 812 px, снизу возвращается полоса, нижняя навигация смещается. Прямо запрещено постановкой. |
| Отрицательный отступ / сдвиг контента | **Отклонён** постановкой и по сути: контент уехал бы под индикаторы. |
| Новый декоративный слой сверху | **Отклонён:** страница системную область не рисует, слой её не закрасит. |
| **`theme-color` = цвет верха сцены** | **Выбран.** Поддерживаемый механизм, геометрия вьюпорта не меняется, разметка и CSS экранов не трогаются. Худший случай (если версия iOS игнорирует `theme-color` в standalone) — остаётся как сейчас, регрессии нет. |

## Что изменено

**`index.html`**

1. Два мета-тега `theme-color` (по системной схеме) заменены одним, управляемым приложением:
   `<meta name="theme-color" id="themeColorMeta" content="#9dc1f3">`. Теперь цвет следует
   **теме приложения**, а не системной схеме — расхождение из `TASK_011` закрыто.
2. Новый токен палитры `--status-bar`: `#9dc1f3` (светлая), `#1e325b` (тёмная). Значения не
   выдуманы, а **замерены**: средний цвет фактической верхней строки сцены hero за 40
   моментов анимации (светлая: среднее `#9dc1f3`, диапазон `#7395d8…#bde5ff`; тёмная:
   среднее `#1e325b`).
3. `applyTheme()` вызывает новую `syncStatusBarColor()` — она читает `--status-bar` уже
   применённой темы и пишет в мета-тег. Единственный источник правды — палитра, как у
   `--hero-gl-*` в `AF.HeroCanvas.readPalette()`.

**`manifest.json`**

4. `theme_color`: `#0f1115` → `#9dc1f3` — согласован с мета-тегом (прежде противоречил ему).
   `background_color` (экран запуска) намеренно **не трогал**: это другая сущность, и его
   изменение здесь не проверить.

Чего **не** менял: `apple-mobile-web-app-status-bar-style` остался `default`; геометрия
вьюпорта, шапка, отступы, нижняя навигация, градиенты и анимация волн, тёмная тема сцены,
карточки — без изменений.

## Насколько шов стал незаметнее (расчёт по замеренным цветам)

| | Было | Стало |
|---|---|---|
| Светлая: контраст системной области и верха сцены | 1.71 : 1 | **1.00 : 1** |
| Светлая: худший случай (край диапазона анимации) | 2.77 : 1 | **1.62 : 1** |
| Тёмная: контраст | 1.50 : 1 | **1.00 : 1** |

`1.00 : 1` — шов неотличим по яркости. Полностью постоянным он быть не может: фон сцены
медленно анимируется, а системная область — плоский цвет; остаточная разница в пределах
`1.62 : 1` в крайних фазах анимации.

## Проверки

**Тесты:** `3750 passed, 0 failed`, 42 файла, код выхода 0 у каждого (прогон на финальном
состоянии рабочего дерева).

**Цвет следует теме приложения, а не схеме устройства.** Матрица прогнана дважды — при
эмулированной системной схеме `dark` и `light`; значение читалось из живого мета-тега:

| Тема приложения | Системная схема | `data-theme` | `theme-color` |
|---|---|---|---|
| Светлая | **тёмная** | light | **`#9dc1f3`** |
| Тёмная | тёмная | dark | `#1e325b` |
| Системная | тёмная | dark | `#1e325b` |
| Светлая | светлая | light | `#9dc1f3` |
| Тёмная | **светлая** | dark | **`#1e325b`** |
| Системная | светлая | light | `#9dc1f3` |

Решающие строки — выделенные: при системной тёмной схеме светлая тема приложения даёт
голубой `#9dc1f3`. Прежний код (`media="(prefers-color-scheme: dark)"`) дал бы там почти
чёрный `#0f1115`. Зависимость исключительно от схемы устройства устранена.

**Реальный путь пользователя** (кнопка смены темы, `toggleTheme()`), три нажатия подряд:
тёмная → `#1e325b`, системная → `#9dc1f3`, светлая → `#9dc1f3`. Обновление происходит
синхронно со сменой `data-theme`.

**Согласованность значений** (сверено в файлах):
`meta theme-color` = `--status-bar` светлой темы = `manifest.theme_color` = `#9dc1f3`;
`--status-bar` тёмной = `#1e325b`. Мета-тег `theme-color` ровно один; токен `--status-bar`
объявлен ровно дважды (светлая + тёмная); `manifest.json` — валидный JSON.

**Геометрия не затронута** (совпадает до и после изменения):
`.app [0, 812]`, `.finance-ambient [0, 812]`, `.topbar [0, 64]`, `.scroll-area [64, 812]`,
**`.nav [742, 806, 64]`**; горизонтального скролла нет.

**Временной диагностики не осталось:** `debug-safearea.js` удалён с диска, упоминаний в
`index.html` / `manifest.json` / `sw.js` / `js/` / `tests/` нет,
`apple-mobile-web-app-status-bar-style` = `default`. Правки затрагивают только
`index.html` и `manifest.json`; `js/core/app_info.js`, `sw.js` и `tests/` не изменялись.

**Визуально:** шов симулирован в превью (полоса 47 px над страницей, только в рантайме) —
при `#f4f6fb` белая полоса воспроизводится, при `#9dc1f3` сливается с фоном.

## Что остаётся неподтверждённым без реального iPhone

1. **Красит ли iOS статус-бар по `theme-color` в standalone-режиме.** Открытые источники
   противоречат друг другу, версия iOS имеет значение, полного Xcode и Simulator на машине
   нет. Если конкретная версия iOS мета-тег игнорирует — полоса останется прежней; ухудшения
   при этом не будет. В обычном Safari (iOS 15+) эффект ожидается в любом случае.
2. **Точность совпадения оттенка на устройстве** — зависит от цветового профиля экрана.
3. Проверка в превью **не является** доказательством поведения системного статус-бара iOS.
4. **Режим «Системная тема»**: слушателя смены схемы ОС в проекте нет (`matchMedia` читается
   только внутри `applyTheme()`), поэтому при переключении темы устройства на лету цвет
   обновится лишь после перезагрузки или смены темы в приложении. Это **существующее
   поведение всего интерфейса** (так же ведёт себя `data-theme`), а не регрессия этой
   задачи; исправление затронуло бы логику тем и в границы TASK_065 не входит.

## Побочное наблюдение (не дефект этой задачи)

На экранах-оверлеях (Профиль, страница операции) фон не голубой, поэтому системная область
будет слегка контрастировать с ними. Это меньшее расхождение, чем белое-на-голубом на пяти
основных экранах; менять цвет динамически по экрану — отдельная задача, здесь не делалось.
