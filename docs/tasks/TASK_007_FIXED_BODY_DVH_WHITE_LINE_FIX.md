## Проблема (со слов пользователя)

После `TASK_006` (шапка/`body` зафиксированы через `position:fixed`) на
реальном iPhone/PWA пользователь увидел белую линию внизу экрана, которой
не было раньше — попросил убрать её и вернуть поведение «как было».

## Диагноз

`html`/`body` в `TASK_006` получили `height:100%`/`height:100%` без фона
на `html`. На iOS Safari высота layout-viewport (`100%`/`100vh`) не всегда
совпадает с реальной видимой областью экрана при показе/скрытии панели
адреса — `position:fixed` элемент, высота которого посчитана по «большему»
layout-viewport, может не дотягиваться до фактического нижнего края
видимой области при её сокращении, обнажая дефолтный белый фон `html`
(`background` на `html` не был задан вовсе — только на `body`). Это и есть
«белая линия внизу».

## Цель

Убрать белую линию, не отменяя исправление rubber-band из `TASK_006`
(шапка должна остаться неподвижной).

## Границы работы

- Затронуть только CSS-правила `html`/`body` (высота + фон).
- Не менять `.app`/`.scroll-area`/`.topbar`/HTML-структуру, JS-слушатели
  `TASK_006`, `.month-switch`/`TASK_005`, финансовую карточку, список
  операций, нижнюю навигацию.

## Реализация

- `html`: `height:100%` → `height:100vh;height:100dvh` (прогрессивное
  улучшение — `100dvh` переопределяет `100vh` в браузерах, которые его
  поддерживают, и реагирует на реальное изменение видимой области при
  показе/скрытии панели Safari, в отличие от статичного `100vh`); добавлен
  `background:var(--bg)` — даже остаточный зазор будет в цвет темы, а не
  белым.
- `body` (уже `position:fixed;inset:0` из `TASK_006`): `height:100%` →
  `height:100vh;height:100dvh` по той же причине.
- `.app` не менялся (`height:100%` от `body`, который теперь сам корректно
  отслеживает реальный viewport).
- `sw.js`: версия кэша поднята `finance-v147` → `finance-v148`.

## Проверки выполнены

- Синтаксис инлайн-скрипта — без ошибок.
- Браузер предпросмотра (375×812, светлая и тёмная тема):
  - `getComputedStyle(html).backgroundColor` совпадает с `var(--bg)`
    активной темы (`rgb(255,255,255)` светлая / `rgb(15,17,21)` тёмная).
  - `html`/`body` computed height === `window.innerHeight`.

  - Ошибок в консоли браузера нет.

## Известные ограничения

- Точный WebKit-баг (расхождение layout- и visual-viewport при
  показе/скрытии панели Safari) специфичен для iOS Safari и не
  воспроизводился в Chromium-движке браузера предпросмотра этой сессии —
  там были проверены только вычисленные стили (`dvh` применяется, фон
  `html` соответствует теме) и отсутствие регрессий в остальном поведении.
