# TASK_046 — Полный текст операции в карточках дня на Главной (перенос строк вместо обрезания)

**Статус:** DONE (commit + push в `main`)

## Контекст

На Главной (`#recentList`, `homeTxRow()`/`homeGroupedTxHtml()`) заголовок
операции (`.home-title` — категория) и подзаголовок (`.home-sub` — время ·
подкатегория/получатель · примечание) обрезаются многоточием:
`white-space:nowrap;overflow:hidden;text-overflow:ellipsis`. Длинное
описание (например, «Одежда Снежана · Брюки, юбка, кофта и зимняя куртка»)
показывается частично: «Одежда Снежана · Кофта 2 …».

`.home-title`/`.home-sub`/`.home-tx`/`.home-daycard` — общие классы,
переиспользуемые и «Операциями по категории» (`catxGroupedTxHtml`,
`TASK_041`); правка CSS затронет оба экрана — это ожидаемо (тот же
компонент), отдельная задача на это не заводится.

## Цель

Заголовок и подзаголовок операции показываются полностью, перенос на
несколько строк вместо обрезания; строка операции и карточка дня растут
под контент; соседние операции, разделители и суммы не ломаются; на 320 px
и 390 px нет горизонтальной прокрутки.

## Границы работы

Разрешено: CSS-правила `.home-title`, `.home-sub`, `.home-acc` (в файле
`index.html`, блок стилей Главной, TASK_004); новый статический тест;
документация.

Запрещено: JS-логика дат/времени/сортировки/сумм (`homeTxRow()` markup —
только если потребуется, без изменения того, ЧТО отображается, только как);
`.tx`/`.t1`/`.t2`/`.daycard` (экран «Все операции», счёт — не переиспользуют
`.home-*`, вне запроса пользователя); `sw.js` версия — CSS встроен в
`index.html`, отдельного кэшируемого файла нет, но версия кэша всё равно
поднимается (байты `index.html` в precache).

## Требования

1. `.home-title`/`.home-sub`: убрать `white-space:nowrap`,
   `overflow:hidden`, `text-overflow:ellipsis` — текст переносится
   (`overflow-wrap:break-word` на случай одного длинного слова без
   пробелов).
2. Высота строки/карточки — не фиксирована нигде (подтверждено: ни
   `.home-tx`, ни `.home-body`, ни `.home-daycard` не задают `height`),
   растёт автоматически за счёт нормального flow.
3. `.home-acc` (способ оплаты/счёт) — нельзя оставлять неограниченным
   `nowrap` без защиты: получает `max-width` + `overflow:hidden` +
   `text-overflow:ellipsis`, чтобы аномально длинное имя счёта не породило
   горизонтальный скролл строки (описание операции при этом не обрезается
   — обрезание применяется только к способу оплаты, не к
   заголовку/подзаголовку).
4. `align-items:center` на `.home-tx`/`.home-body` не меняется — при
   росте высоты `.home-main` иконка и `.home-side` (счёт/сумма)
   центрируются по высоте выросшей строки, не перекрывают текст (обычное
   поведение flex-строки, элементы не накладываются).

## Результат (фактически)

### Что реализовано

- `.home-tx .home-title`/`.home-sub`: `white-space:nowrap;overflow:hidden;
  text-overflow:ellipsis` заменены на `white-space:normal;overflow-wrap:
  break-word` — заголовок (категория) и подзаголовок (время · подкатегория/
  получатель · примечание) переносятся на нужное число строк вместо
  обрезания. Ни один контейнер (`.home-tx`, `.home-body`, `.home-daycard`)
  не задаёт `height`/`max-height` — карточка дня растёт под контент сама,
  правок разметки/JS не потребовалось.
- `align-items:center` на `.home-tx`/`.home-body` не менялся: иконка и
  правый блок (счёт/сумма) центрируются по высоте выросшей строки — flex-
  элементы в ряд никогда не перекрываются, наложения текста нет ни на
  одном из проверенных сценариев.
- `.home-tx .home-acc` (способ оплаты/счёт) — оставлен `white-space:nowrap`,
  добавлены `overflow:hidden;text-overflow:ellipsis;max-width:120px`: это
  не «описание операции» (которое требование запрещает обрезать), а
  короткая метка — защита нужна, чтобы аномально длинное имя счёта не
  вызвало горизонтальный скролл строки.
- `sw.js`: `finance-v177` → `finance-v178` (байты `index.html` изменились).
