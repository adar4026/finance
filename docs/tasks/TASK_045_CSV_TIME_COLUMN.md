# TASK_045 — Колонка «Время» в CSV-экспорте и импорте

**Статус:** DONE (commit + push в `main`)

## Контекст

`TASK_044` добавила операции необязательное поле `time` (`'HH:MM'`) и
исправила порядок внутри дня на всех экранах. Известное ограничение,
зафиксированное в результате `TASK_044`: «CSV/XLSX-экспорт и импорт CSV не
знают поле `time` (колонка не добавлена — вне границ задачи)». Пользователь
попросил закрыть это для CSV (экспорт и импорт); XLSX/HTML-отчёт — не
запрошены, остаются вне границ.

## Цель

1. CSV-экспорт (`AF.Services.Export.csv`) пишет время операции отдельной
   колонкой «Время» (`'HH:MM'`, пусто у операций без времени).
2. CSV-импорт умеет прочитать колонку «Время» (в т.ч. своего же экспорта —
   round-trip) и записать `tx.time`; резервно — вытащить `HH:MM` из самой
   колонки «Дата», если отдельной колонки времени нет, а дата содержит время
   (`01.02.2024 14:30`), как многие банковские экспорты.
3. Существующий формат не ломается: новая колонка добавляется в конец (после
   «Примечание»), позиции колонок 0–11 не меняются — минимальный риск для
   уже принятого regression-контракта `tests/export_service.test.js` (12
   колонок в утверждённом порядке, `TASK_015 ОВ-3`).

## Границы работы

Разрешено:

- `js/services/export_service.js` — колонка «Время» в `csv()` (конец
  строки), новый `_time(t)`;
- `js/services/import_source_service.js` — новое поле `time` в `FIELDS`,
  правило автосопоставления в `RULES`, `AF_CSV_HEAD` (распознавание
  собственного экспорта);
- `js/services/import_service.js` — разбор колонки времени
  (`AF.Services.TxTime.normalize` с резервным разбором без сервиса —
  инвариант `TASK_015 §0`), резервное извлечение времени из ячейки даты,
  запись `tx.time` для операций и переводов;
- тесты (`tests/export_service.test.js`, `tests/import_service.test.js` —
  добавление проверок; существующие проверки не переписываются логически,
  только дополняются недостающим полем там, где считают точное число
  колонок);
- документация (`TASK_045`, `PROJECT_STATUS`, `ROADMAP`, `CHANGELOG`).

Запрещено:

- `xlsHtml`/`xlsxColumns`/`xlsxRows`/`reportHTML` (XLS/XLSX/PDF) — не
  запрошены, вне границ;
- порядок и состав колонок 0–11 CSV, формат JSON/`.afb`;
- `AF.Services.TxTime` (сервис `TASK_044` не меняется, только используется);
- модель операции, сортировка, форма — уже сделаны в `TASK_044`.

## Требования

1. `csv()`: заголовок получает 13-ю колонку «Время» в конце; значение —
   `t.time` при наличии, иначе пусто (и для расхода/дохода, и для перевода).
2. `import_source_service.js`: колонка «Время»/«Time»/«Hora» и т.п.
   автоматически определяется в мастере импорта (используется общий
   механизм `FIELDS`/`impRenderMapping` — правки `index.html` не нужны).
   `AF_CSV_HEAD` учитывает новую колонку — собственный экспорт с временем
   по-прежнему опознаётся как «A-Lex Finance» с высокой уверенностью.
3. `import_service.js`: если колонка «Время» сопоставлена и содержит
   валидное `HH:MM` (или разбираемое, напр. `9:5`, `14:30:00`) — `tx.time`
   заполняется; если колонка не сопоставлена или пуста, но ячейка «Дата»
   содержит `HH:MM` (напр. `01.02.2024 14:30`) — время достаётся оттуда;
   иначе `tx.time` не создаётся («пусто = ключа нет», как всё остальные
   метаданные). Работает для операций и переводов.
4. Round-trip: CSV, экспортированный этой же версией приложения (с
   заполненным временем), при повторном импорте восстанавливает `tx.time` с
   тем же значением.
5. Дубликаты (`fingerprint`) не учитывают время — поведение обнаружения
   повторного импорта не меняется (это уже проверено `TASK_038`/`import_service.test.js`
   §6, регрессия недопустима).

## Критерии готовности / план проверок

- `tests/export_service.test.js`: колонка «Время» — 13-я, в конце; пустая
  для операций без времени; содержит значение при наличии; round-trip чтения
  через тот же самодельный `parseCsv`.
- `tests/import_service.test.js`: автосопоставление «Время»; импорт строки
  с явной колонкой времени → `tx.time`; импорт даты с встроенным временем без
  отдельной колонки → `tx.time` из даты; отсутствие времени → ключа нет;
  round-trip с `AF.Services.Export.csv` → `AF.Services.Import.buildPlan`;
  детектор источника (`SRC.detect`) по-прежнему различает «A-Lex Finance» с
  новой колонкой.
- Regression: все `tests/*.test.js` — 0 failed.
- Ручная проверка в preview: экспорт CSV операции со временем → открыть файл
  → колонка «Время» на месте; импорт этого же файла обратно → операция
  восстановлена с тем же временем и встаёт в правильное место дня.

## Результат (фактически)

### Что реализовано

- `AF.Services.Export.csv()` — 13-я колонка «Время» добавлена **в конец**
  строки (после «Примечание»), позиции 0–11 (контракт `TASK_015 ОВ-3`) не
  тронуты. Значение — `t.time` при наличии, иначе пусто; новый `_time(t)`
  читает поле защитно (тот же приём, что `_payee`/`_tags`/`_place`).
- `AF.Services.ImportSource` — новое поле `time` в `FIELDS` (появляется на
  экране сопоставления колонок автоматически — правок разметки `index.html`
  не потребовалось, экран строится из `FIELDS`), правило автосопоставления
  в `RULES` (`время`/`time`/`hora`/`uhrzeit`/…), `AF_CSV_HEAD` дополнен
  `'время'` в конце — собственный экспорт с новой колонкой по-прежнему
  опознаётся как «A-Lex Finance» с высокой уверенностью.
- `AF.Services.Import` — `parseTimeCell()` (через `AF.Services.TxTime.normalize`
  с резервным разбором `HH:MM` без сервиса — инвариант `TASK_015 §0`) и
  `extractTimeFromDate()` (резервное извлечение времени из самой ячейки
  «Дата», когда отдельной колонки нет — банковские/Money Flow экспорты
  часто пишут дату и время вместе: «01.02.2024 14:30»). `applyTime()` —
  «пусто = ключа нет», применяется в обеих ветках построения плана (перевод
  и расход/доход). `time` НЕ добавлено в `fingerprint()` — обнаружение
  дубликатов не изменилось (проверено отдельным тестом).
- `sw.js`: `finance-v176` → `finance-v177` (байты трёх изменённых сервисов).

### Известные ограничения

- `xlsHtml`/`xlsxColumns`/`xlsxRows` (Excel-экспорт) и PDF-отчёт
  (`reportHTML`) колонку времени не получили — не запрошены, вне границ
  задачи.
- Резервное извлечение времени из ячейки «Дата» берёт первое вхождение
  `HH:MM` в строке; для колонок с посторонним текстом, где раньше времени
  встречается похожая на время подстрока, это теоретически может дать
  ложное совпадение — риск признан приемлемым (тот же уровень эвристики,
  что и остальной разбор дат в этом сервисе).
