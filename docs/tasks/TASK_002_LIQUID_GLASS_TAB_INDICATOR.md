# TASK_002 — Liquid Glass Tab Indicator

- **Номер:** TASK_002
- **Название:** Liquid Glass Tab Indicator
- **Статус:** DONE

## Цель

Добавить в существующую нижнюю навигацию A-Lex Finance один общий плавно
перемещающийся индикатор активного раздела с эффектом Apple Liquid Glass —
не меняя структуру панели, маршруты и центральную кнопку добавления операции.

## Текущее состояние нижней панели (на момент начала задачи)

Подтверждено чтением `index.html` на `HEAD=023ef92`:

- Разметка — `<div class="nav">` с пятью кнопками: `data-s="scrRecords"`,
  `data-s="scrCharts"`, `#addBtn.addbtn` (без `data-s`), `data-s="scrAccounts"`,
  `data-s="scrBudgets"`.
- Активная вкладка получает класс `.on` через
  `showScreen()` → `$$('.nav button[data-s]').forEach(b=>b.classList.toggle('on', b.dataset.s===id))`.
- Активное состояние сейчас — **точечное**: `.nav button.on{color:var(--nav-blue);background:var(--nav-active-bg)}`
  задаёт заливку прямо на самой кнопке, без общего перемещающегося элемента.
- Центральная кнопка «Добавить» (`#addBtn`) не имеет `data-s`, её обработчик
  (`$('#addBtn').onclick=()=>$('#addMenu').classList.add('show')`) никогда не
  вызывает `showScreen()` — значит она уже не участвует в переключении
  активной вкладки (нет риска, что индикатор «залипнет» под ней).
- `.nav` — `position:fixed`, `display:flex`, четыре маршрутные кнопки —
  `flex:1 1 0` (равная ширина, зависящая от ширины экрана), кнопка «+» —
  `flex:0 0 68px`. Ширина и позиция кнопок не фиксированы в px — зависят от
  ширины экрана и `clamp()` для шрифта подписи.
- При экране `scrMore` (открывается через drawer, не через `.nav`) ни одна
  из четырёх кнопок не получает `.on` — активной вкладки в нижней навигации
  нет вообще. Это существующее поведение, не вводится этой задачей.
- Safe area уже обрабатывается на уровне `.nav` (`bottom:max(6px, env(safe-area-inset-bottom))`).
- Токены темы `--nav-blue`, `--nav-blue2`, `--nav-blue-soft`, `--nav-active-bg`,
  `--nav-shadow` уже определены отдельно для светлой и тёмной темы.

## Границы задачи

- Только нижняя навигация (`.nav` и её содержимое) в `index.html`.
- Верхняя панель, экраны, данные, маршруты, форма операции — не трогаются.

## Функциональные требования

1. Один общий индикатор перемещается между четырьмя маршрутными вкладками.
2. Индикатор рассчитывает позицию по фактической геометрии активной кнопки
   (JS, `getBoundingClientRect`/`offset*`) — не по жёстко заданным координатам.
3. Индикатор не остаётся под кнопкой «Добавить» — она не участвует в
   переключении активной вкладки (уже верно в текущем коде).
4. Индикатор корректно позиционируется: при первой загрузке, после
   переключения раздела, после изменения ширины окна/ориентации, при
   ширинах 320/375/390/430 px, в обеих темах, с учётом safe area.
5. Открытие формы операции через «+» не сдвигает индикатор с предыдущей
   активной вкладки.
6. При экране `scrMore` (без активной кнопки в `.nav`) индикатор аккуратно
   скрывается (opacity), а не прыгает в произвольную точку.

## Визуальные требования

- Компактная симметричная капсула со скруглением, соответствующим текущему
  скруглению активной кнопки (`border-radius:18px`).
- Полупрозрачное стекло: светлая тема — светлый холодный сине-фиолетовый
  тон (на основе уже существующего `--nav-active-bg`/`--nav-blue-soft`);
  тёмная тема — отдельная, не инвертированная адаптация с видимой границей.
- `backdrop-filter: blur(...) saturate(...)` как прогрессивное улучшение;
  базовый вид (градиент + граница + тень) остаётся читаемым без него.
- Тонкая полупрозрачная обводка, мягкая внешняя тень, едва заметный
  внутренний блик.
- Активная иконка/подпись — синий акцент, поверх индикатора (z-index),
  контраст сохраняется.
- Без неонового свечения, без тяжёлой непрозрачной плашки, без порчи
  контраста подписей.

## Анимация

- Перемещение через `transform` (без влияния на layout соседних элементов).
- Длительность ~260–280 мс, мягкая пружинная кривая.
- Лёгкое растяжение по направлению движения с возвратом к обычной форме —
  реализуется через Web Animations API (`Element.animate`), рассчитывается
  от фактической текущей позиции индикатора (`getBoundingClientRect`), что
  корректно обрабатывает быстрое повторное переключение (отмена текущей
  анимации перед стартом новой).
- `@media (prefers-reduced-motion: reduce)` — переключение без анимации,
  индикатор сразу занимает новую позицию.

## Фактически реализовано

Реализовано ровно то, что было запланировано (см. разделы выше), без
отклонений от границ задачи. Изменён только `index.html`.

### CSS

- Новые токены `--nav-glass-bg` / `--nav-glass-border` / `--nav-glass-shadow`,
  отдельно для `:root,[data-theme="light"]` и `[data-theme="dark"]`.
  Светлая тема — белый градиент (68%→30% непрозрачности) поверх уже
  существующего `--nav-active-bg` (`--nav-blue-soft`). Тёмная тема — не
  инверсия, а отдельная более тёмная стеклянная адаптация (белый градиент
  4–14% непрозрачности) с более заметной обводкой (20% против 75% в
  светлой) для сохранения контраста.
- `.nav button.on` больше не красит саму кнопку фоном — только цвет текста/иконки
  (`color:var(--nav-blue)`); заливку теперь несёт `.nav-indicator`.
- `.nav button` получил `position:relative;z-index:1`, чтобы иконка и подпись
  всегда были поверх стеклянного индикатора (`.nav-indicator{z-index:0}`).
- `.nav-indicator` — `position:absolute` внутри `.nav` (которая `position:fixed`
  и служит offsetParent), `border-radius:18px` (то же скругление, что и у
  активной кнопки), `backdrop-filter:blur(14px) saturate(160%)` как
  прогрессивное улучшение поверх уже читаемого градиент+граница+тень фолбэка.
- `@media (prefers-reduced-motion: reduce)` — сокращает transition
  width/height до почти нулевой длительности (фактическое переключение и так
  идёт по mgновенной JS-ветке при этом media-query).

### JS

- `moveNavIndicator(instant)` — считает целевую позицию/размер по
  `getBoundingClientRect()` активной кнопки относительно `.nav`, без
  жёстко заданных координат.
  - Анимированный путь (переключение вкладки, `instant` не передан): через
    `Element.animate()` — три кадра `translate(...) scaleX(...)` с лёгким
    растяжением (до ×1.16) по направлению движения на середине пути и
    возвратом к `scaleX(1)` в конце; `duration:270ms`,
    `easing:cubic-bezier(.34,1.1,.4,1)` (мягкая пружинная кривая).
    Стартовая точка анимации — фактическая текущая geometry индикатора
    (`getBoundingClientRect`), считанная **до** отмены предыдущей анимации,
    поэтому быстрые повторные переключения не дают видимого скачка.
  - Мгновенный путь (`instant===true`, `prefers-reduced-motion: reduce`,
    первая отрисовка или отсутствие `Element.animate`): временно
    `transition:none`, применяется целевой `transform`/`width`/`height`,
    затем принудительный reflow и возврат transition — без анимации и без
    краткого несоответствия ширины панели (см. «Технические решения» ниже).
  - Если активной кнопки нет (экран `scrMore`) — индикатор скрывается через
    `classList.remove('ready')` → `opacity:0`, позиция сохраняется для
    плавного появления при возврате на маршрутный экран.
- Вызов `moveNavIndicator()` добавлен в `showScreen()` сразу после
  переключения класса `.on` — единственная точка интеграции с существующей
  бизнес-логикой экранов.
- `window resize` (с debounce 80мс) и `orientationchange` (задержка 120мс)
  вызывают `moveNavIndicator(true)` — мгновенное перепозиционирование без
  анимации.
- `ResizeObserver` на `.nav` — основной надёжный триггер репозиционирования
  при любом изменении фактических размеров панели (ресайз, поворот,
  системный масштаб), независимо от того, дошло ли до страницы событие
  `resize`.
- `#addBtn` по-прежнему не вызывает `showScreen()` — индикатор гарантированно
  не перескакивает на кнопку «Добавить».

### Технические решения

- **Позиционирование через JS, не через CSS `nth-child`**: кнопка «Добавить»
  разрывает равномерность grid/nth-child паттерна (не участвует в
  переключении вкладок, другая ширина), а четыре маршрутные кнопки имеют
  переменную ширину (`flex:1 1 0`, зависит от ширины экрана и `clamp()`
  шрифта подписи) — жёсткие CSS-координаты были бы ненадёжны. JS по
  `getBoundingClientRect` — минимально сложное решение, покрывающее все
  требуемые ширины без дублирования брейкпоинтов.
- **Найден и исправлен баг во время проверки**: при переносе позиции
  индикатора «на лету» код сначала читал `getBoundingClientRect()` (для
  вычисления стартовой точки анимации) и только потом отменял предыдущую
  WAAPI-анимацию — верный порядок, иначе `cancel()` откатывает рендер к
  старой inline-позиции и даёт видимый скачок на быстрых повторных тапах.
  Это было проверено и исправлено на этапе реализации (см. историю правок),
  прежде чем перейти к проверкам по чек-листу.
- **Найден и исправлen второй баг при проверке ресайза**: изначально при
  ресайзе окна `moveNavIndicator()` вызывался без «мгновенного» режима, из-за
  чего CSS `transition:width .2s ease` на `.nav-indicator` заставлял ширину
  индикатора «доезжать» до новой geometry панели уже после того, как сама
  панель мгновенно перестроилась под новую ширину экрана — на короткое время
  (до ~200мс) индикатор мог быть заметно шире набора кнопок и выходить за
  правый край панели. Исправлено: ресайз/поворот/первая отрисовка используют
  отдельную «мгновенную» ветку (`transition:none` + forced reflow), анимация
  через `Element.animate()` осталась только для реальных переключений вкладки.
  Численно подтверждено (`getBoundingClientRect`) отсутствие overflow на всех
  проверенных ширинах после исправления.
- **`ResizeObserver` добавлен как основной триггер, а не только `resize`**:
  при проверке в песочнице предпросмотра выяснилось, что эмулированный ресайз
  вьюпорта не всегда синхронно доходит до `window resize`/`ResizeObserver`
  колбэков без принудительного рендер-пасса (особенность headless-окружения
  предпросмотра, не самого браузера) — ручной вызов `moveNavIndicator(true)`
  всегда давал корректный результат, что подтвердило верность самой геометрии
  расчёта. `ResizeObserver`, слушающий `.nav` напрямую, — более надёжный
  способ поймать любое изменение размеров панели в реальном браузере
  (повороты, системный масштаб), чем полагаться только на `window resize`.

## Известные ограничения

- Небольшое (≤3px) суб-пиксельное расхождение между geometry индикатора и
  активной кнопки на некоторых ширинах — артефакт округления дробной ширины
  flex-элементов (`flex:1 1 0` на нецелое количество px), визуально не
  заметно, не создаёт overflow.
- Растяжение/сжатие индикатора при движении (Web Animations API) не
  проверялось на реальном iPhone/Safari в этой сессии — только в браузере
  предпросмотра; логика реализована на широко поддерживаемых стандартных API
  (`Element.animate`, `ResizeObserver`), деградирует до мгновенного
  позиционирования там, где `Element.animate` недоступен.
- В использованном headless-окружении предпросмотра `window resize` и
  `ResizeObserver` колбэки не всегда доходят синхронно без принудительного
  рендер-пасса (особенность инструмента предпросмотра) — сама логика
  позиционирования проверена вызовом напрямую и даёт верный результат;
  `ResizeObserver` добавлен как более надёжный (по сравнению с одним `resize`)
  механизм для реальных браузеров.
