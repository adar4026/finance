## 1. Контекст

Пользователь прислал скриншот production-экрана «Бюджеты»
(`finance-v166`, после `TASK_022`/`TASK_023`) и отметил: строка
«Потрачено €681,62 / Лимит €850» внутри фиолетово-голубой
герой-карточки «Осталось в бюджете» отображается приглушённым серым
текстом и плохо читается на градиенте — нужно сделать шрифт белым.

## 2. Причина (найдена до правки)

Герой-карточка получает в JS класс `capital bud-hero`
(`bt.className='capital bud-hero'`, `index.html:3365`). Общий класс
`.capital{color:#fff}` (`index.html:1414`) красит текст карточки в
белый по наследованию. Строка «Потрачено/Лимит» рендерится как
`<div class="bh-foot"><span>...</span><span>...</span></div>`
(`index.html:3375`).

Оказалось, что в CSS есть **два** правила `.bh-foot`:

- `.bud-hero .bh-foot{...}` (`index.html:1292`) — задаёт только
  `font-size`/`margin-top`/`opacity`, **цвет не задаёт**.
- `.bh-foot{color:var(--muted2)}` (`index.html:1405`) — общее правило
  (изначально для другого, неиспользуемого набора `.bh-head`/`.bh-title`/
  `.bh-sub`, `index.html:1400-1406` — по разметке эти три класса нигде
  не используются, мёртвый CSS вне границ этой задачи).

`color` — наследуемое свойство, поэтому браузер выбирает победителя
среди **всех** правил, которые явно задают `color` для самого элемента
`span` внутри `.bh-foot`, либо для его предков (наследование). Правило,
заданное **непосредственно** на элементе (`.bh-foot{color:var(--muted2)}`),
всегда побеждает наследуемое значение от `.capital`, независимо от
специфичности предка — отсюда серый, а не белый текст.

## 3. Цель

Строка «Потрачено/Лимит» внутри герой-карточки бюджета должна быть
белой и хорошо читаться на градиенте, как и весь остальной текст
карточки.

## 4. Границы

**Включено:**

- Один явный `color:#fff` на `.bud-hero .bh-foot` (`index.html:1292`) —
  специфичность (0,2,0) выше, чем у общего `.bh-foot` (0,1,0), поэтому
  переопределяет его гарантированно и однозначно, без побочных эффектов
  для чужих потребителей класса `.bh-foot`.
- Bump версии кэша `sw.js`.
- Точечный regression-тест в `tests/budgets_screen.test.js`.

**Не включено:**

- Мёртвые `.bh-head`/`.bh-title`/`.bh-sub` (`index.html:1400-1402`) — не
  используются нигде в разметке, не относятся к сообщённому дефекту, вне
  границ этой точечной правки.
- `.bh-empty` (пустое состояние герой-карточки) — тот же класс наследования
  теоретически применим и к нему (`index.html:1406` тоже красит в
  `var(--muted2)`), но пользователь сообщил конкретно про «Потрачено» —
  пустое состояние на прислан­ном скриншоте не показано и отдельно не
  запрошено. Оставлено как отдельно фиксируемое наблюдение, а не
  включено в эту задачу без запроса (см. §7).
- Любая расчётная логика бюджетов, данные, другие экраны — не тронуты.

## 7. Известное наблюдение (не входит в эту задачу)

`.bh-empty` (текст пустого состояния герой-карточки, «Бюджеты не
заданы…») подвержен той же причине (общее `.bh-empty{color:var(--muted2)}`,
`index.html:1406`, побеждает наследуемый белый от `.capital`) и тоже
может читаться приглушённо на градиенте. Пользователь эту строку не
показывал и не просил — оставлено как отдельное наблюдение на будущее,
не исправлено без прямого запроса.
