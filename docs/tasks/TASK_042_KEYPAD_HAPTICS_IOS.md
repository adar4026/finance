# TASK_042 — Тактильный отклик цифровой клавиатуры на iPhone

**Статус:** DONE (локально; commit без push — по требованию постановки; ощущение
отклика требует подтверждения на реальном iPhone пользователя, iOS 18+)

## Этап 1 — технический анализ (выполнен до реализации)

### Архитектура (подтверждено кодом)

- Приложение — **чистый статический сайт / PWA** без сборки и фреймворка
  (`index.html` + `js/**`), публикуется на GitHub Pages
  (`https://adar4026.github.io/finance/`). Нативной оболочки (Capacitor /
  Cordova / WKWebView-проект / Xcode) **нет**; `finance.mobileconfig` — лишь
  конфигурационный профиль, не приложение.
- На iPhone запускается как **standalone PWA** («На экран Домой»,
  `apple-mobile-web-app-capable`, `manifest.json: display: standalone`), т.е.
  внутри системного WebKit — тот же движок, что Safari.
- Цифровая клавиатура — `#keypadDock .keypad button[data-k]`
  (`index.html:2113–2125`). Обработчики: `b.onclick=()=>key(k)`
  (`index.html:6273`), «Готово» — `#kdDone.onclick=closeKeypad`, ✓ —
  `#saveBtn.onclick=saveTx`. `pointerdown`/`touchstart` на клавишах не
  используются — только `click`.
- Уже существующий отклик: `key()` вызывает `navigator.vibrate(8)`, helper
  `haptic(ms)` (TASK_014) — то же самое. В коде честно помечено:
  «Android; iOS web игнорирует».

### Ответ на вопрос «возможна ли настоящая вибрация на iPhone без Capacitor»

1. **`navigator.vibrate` — НЕТ.** WebKit/Safari на iOS никогда не
   реализовывал Vibration API (`navigator.vibrate === undefined`), в том
   числе в standalone PWA. Текущие вызовы в проекте на iPhone — no-op.
2. **Публичного Web-API для Taptic Engine на iOS — НЕТ.**
3. **НО настоящий системный haptic на iPhone без нативной оболочки —
   ДА, через побочный эффект нативного контрола.** Начиная с iOS 18 WebKit
   при переключении нативного элемента `<input type="checkbox" switch>`
   (появился в Safari 17.4) воспроизводит системный «switch toggle»
   haptic Taptic Engine — тот же лёгкий щелчок, что у системного
   переключателя в Настройках. Программный `label.click()` на связанном
   `<label>` переключает контрол и вызывает этот отклик; работает в Safari
   и в standalone PWA (Home Screen), не требует разрешений, сети и
   задержек. Приём известен и используется в открытых библиотеках
   (`ios-haptics`).
   Оговорки, о которых нужно знать честно:
   - это **недокументированный побочный эффект**, а не API — Apple может
     изменить поведение в будущей версии iOS;
   - доступен только один тип отклика (лёгкий «switch»); «success»
     реализуется как два коротких импульса подряд;
   - требуется **iOS 18+** и включённые «Системные тактильные сигналы»
     (Настройки → Звуки, тактильные сигналы); на iOS ≤ 17 — тишина (без
     ошибок);
   - на Mac в этой сессии проверить физически нельзя (нет iOS Simulator,
     а Simulator и не воспроизводит haptics) — финальное подтверждение
     ощущения требуется на реальном iPhone пользователя.

Вывод: реализация возможна **сейчас, без Capacitor/Xcode**, через
`switch`-приём + `navigator.vibrate` как fallback для Android. CSS-анимация
и Android-вибрация **не** выдаются за решение для iPhone.

## Цель

Лёгкий системный тактильный щелчок при каждом касании клавиши цифровой
клавиатуры формы операции (цифры, `.`/запятая, ⌫, C, `+ − × ÷`, «Готово»)
и чуть более выраженный отклик при **успешном** сохранении операции (✓ /
«Сохранить»). Без звука, без сетевых запросов, без двойных срабатываний.

## Требования

1. Отклик в момент касания (`pointerdown`), не по `click`.
2. Один импульс на одно касание: `click` не вызывает отклик повторно;
   `touchstart` не используется (Pointer Events покрывают touch).
3. Android — `navigator.vibrate` (как раньше), iOS — `switch`-приём;
   среда без обоих — тихий no-op, без исключений.
4. Успешное сохранение — `success()` (два импульса), только когда
   `save()` вернул `ok` (там, где раньше был `haptic(14)`).
5. Существующая логика ввода/расчёта/удаления/сохранения не меняется.

## Критерии готовности

- `AF.Services.Haptics.tap()/success()` покрыты юнит-тестами с fake DOM;
- статические тесты: `key()` больше не вызывает `navigator.vibrate`,
  клавиши слушают `pointerdown`, сервис подключён в `index.html` и `sw.js`,
  версия кэша поднята;
- регрессия: все существующие тесты проходят;
- ручная проверка в браузере (320/390/430 px): ввод `45,52`, `0,50`, `100`,
  запятая, ⌫, C, операции, «Готово», ✓ — расчёт верный, счётчик вызовов
  отклика = числу касаний (без дублей).

### Известные ограничения

- Физическое ощущение на iPhone в этой сессии не проверено (нет iOS
  Simulator на Mac; Simulator и не воспроизводит Taptic Engine). Требуется
  проверка пользователем на реальном iPhone: **iOS 18+**, «Системные
  тактильные сигналы» включены. На iOS ≤ 17 — тишина без ошибок.
- `switch`-приём — недокументированный побочный эффект WebKit; если Apple
  его уберёт, приложение деградирует до прежнего состояния (без отклика),
  не ломаясь. Гарантированный путь на будущее — Capacitor `@capacitor/haptics`
  (см. план ниже).
- Один тип импульса (лёгкий «switch»); `success` = два импульса.
- Активация клавиши с физической клавиатуры (Enter на сфокусированной
  кнопке) отклика не даёт — на iPhone неактуально.
