## Предыстория

`TASK_006`–`TASK_010` — пять последовательных попыток убрать белую полосу
внизу экрана на реальном iPhone. Все пять исправляли **разные слои
вслепую** (высоту `html`/`body`, `dvh`, `position:fixed`, фон
`#scrollArea`) и ни одна не помогла, потому что причина не была доказана —
менялся код, а не проверялась гипотеза. Эта задача останавливает такой
подход: сначала доказательство, потом исправление.

## Что уже доказано (без деплоя)

1. **Геометрия CSS корректна при работающем `viewport-fit=cover`.**
   Chromium всегда отдаёт `env(safe-area-inset-*)` = `0`, поэтому все
   прежние проверки в браузере предпросмотра были бессодержательны. Сделана
   копия приложения с подстановкой реальных значений iPhone
   (`inset-bottom:34px`, `inset-top:47px`) — замеры при 375×812:
   `html/body/.app/#scrollArea` — все `bottom = 812`, `.nav` —
   `bottom = 778` (ровно 34px над краем), фон `#scrollArea` серый до самого
   низа. **Зазора нет.** Значит при корректно применённом `cover` текущий
   CSS белую полосу дать не может.
2. **Исключён `manifest.json` как источник полосы.** `background_color` и
   `theme_color` = `#0f1115` (почти чёрный) — launch surface / фон PWA не
   может выглядеть белым.
3. **Исключён сбой процентной высоты `.app`** (известная особенность
   WebKit): симуляция `.app{height:auto}` даёт другой симптом — ломается
   прокрутка, белой полосы не появляется.
4. **`viewport-fit=cover` присутствует и никогда не терялся** — единственный
   `<meta name="viewport">` в документе, без изменений с самого начала.
   Гипотеза `TASK_010` о потерянном/переопределённом `cover` не
   подтвердилась.
5. **Найдено расхождение (к самой полосе отношения не имеет, но должно быть
   учтено отдельно):** `<meta name="theme-color">` переключается по
   **системной** `prefers-color-scheme`, а тема приложения — по
   `localStorage`/`data-theme`. Плюс `manifest.theme_color` (`#0f1115`)
   противоречит светлому `meta theme-color` (`#f4f6fb`).

## Что доказал пользователь на реальном устройстве

Проведены два дискриминирующих теста (без деплоя):

1. **Переключение темы приложения в тёмную → полоса становится чёрной.**
   ⇒ полоса **внутри страницы** и красится корневым фоном (`--bg`), а не
   системным `theme-color` и не внешним контейнером браузера.
2. **В обычном Safari полосы нет; воспроизводится только в установленной
   standalone PWA.**
   ⇒ проблема специфична для `display-mode: standalone`.

**Промежуточный вывод:** внутри standalone-вьюпорта существует нижняя
область, которую `.app`/`#scrollArea` не перекрывают, и там виден корневой
фон `--bg`. Требуются точные числа именно из standalone, которые
невозможно получить в Chromium.

## Этап 1 (эта итерация): временная debug-сборка

Цель — снять с реального iPhone в standalone-режиме точные значения и
однозначно определить, какой слой перестаёт покрывать экран.

### Что добавлено (временно, подлежит удалению)

- Новый файл `debug-safearea.js` — **не часть приложения**:
  - контрастные фоны корневых слоёв, чтобы по цвету полосы определить
    последний покрывающий слой: `html` — пурпурный, `body` — салатовый,
    `.app` — голубой, `#scrollArea` — оранжевый, `.nav` — красная обводка;
    контент экранов приглушён (`opacity:.35`), чтобы слои просвечивали;
  - панель с замерами: `display-mode: standalone` / `navigator.standalone`,
    `window.innerHeight`, `document.documentElement.clientHeight`,
    `visualViewport.height`/`offsetTop`, `screen.height`, `devicePixelRatio`,
    реальные `env(safe-area-inset-top/bottom)` (через зонд с `padding`),
    `getBoundingClientRect().bottom` для `html`/`body`/`.app`/`#scrollArea`/
    `.nav` с автоматической пометкой `<<< НЕ ДОСТАЁТ Npx`;
  - линейки на `innerHeight`, `clientHeight` и `innerHeight - inset-bottom`;
  - маркер `BUILD debug-1` — подтверждает, что на устройство приехала
    свежая сборка, а не кэш.
- `index.html` — одна строка подключения `debug-safearea.js` (помечена как
  временная).
- `sw.js` — версия кэша `finance-v151` → `finance-v152-debug` (суффикс
  `-debug` намеренно, чтобы отладочная сборка была видна и не перепуталась
  с релизной).

### Проверки

- `node --check debug-safearea.js` — синтаксис в порядке; инлайн-скрипт
  `index.html` — без ошибок.
- Браузер предпросмотра (375×812): панель отображается и читается,
  контрастные фоны применяются, `.nav` обведена, ошибок в консоли нет.
  В Chromium ожидаемо `inset-bottom = 0` и все `bottom = 812`.

### Как снимать данные (для пользователя)

1. Открыть установленную с домашнего экрана PWA (не Safari), дождаться
   свежей версии (маркер `BUILD debug-1` вверху панели).
2. Прокрутить список к самому низу, чтобы полоса была видна.
3. Сделать скриншот целиком (панель + низ экрана с полосой).
4. Ключевое — **какого цвета сама полоса**: пурпурный / салатовый /
   голубой / оранжевый (см. легенду выше) — это и есть виновный слой.
