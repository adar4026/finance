## Цель

Переделать визуальное оформление блока последних операций на Главной
(`#recentList`, экран `#scrRecords`) в светлом минималистичном стиле iOS:
нейтральный серый фон экрана, белые карточки-группы по дням, построчный
список с тонким разделителем, начинающимся после аватарки. Задача только
визуальная — без изменений данных, сортировки, фильтрации, расчётов или
обработчиков.

## Границы работы

- Затронуть **только** рендер списка операций на Главной: функции
  `renderRecent()`, и новые вспомогательные функции для построения разметки
  этого списка, плюс относящийся к ним CSS в `index.html`.
- **Не менять** финансовую карточку (`#finCard`, `.fincard`, `.fc-*`,
  `renderFinanceCard()`) — она уже готова (`TASK_003`/`TASK_003A`).
- **Не менять** переключатель периодов, месяц-свитчер карточки, нижнюю
  навигацию, Liquid Glass — вне границ и явно отложено пользователем.
- **Не менять** общую функцию `groupedTxHtml()`/`txRow()` — они
  переиспользуются на других экранах (модалка «Все операции», категория,
  счёт, бюджет) — тронуть их означало бы затронуть экраны за пределами
  Главной. Вместо этого — отдельные функции только для Главной
  (`homeGroupedTxHtml()`/`homeTxRow()`) и отдельные CSS-классы (`.home-*`),
  не пересекающиеся с `.tx`/`.daycard`, используемыми на других экранах.
- **Не менять** данные операций, аватарки/эмодзи категорий и счетов, логику
  их выбора (`catById`, `subcatById`, `state.accounts.find`), сортировку
  (`b.date.localeCompare(a.date)||b.id-a.id`), группировку по дням,
  обработчик клика по строке (`openSheet`), фильтрацию по периоду
  (`inPeriod`/`periodRange`) и расчёты (`fmtCur`, `signed`, `num`).

## Требования (по постановке пользователя)

1. Фон экрана `#scrRecords` — нейтральный серый (уже `var(--home-bg)`,
   `#f2f2f7` в светлой теме — проверить, что не выглядит белым/цветным).
2. Список операций объединён в белую карточку-группу со скруглёнными
   углами на **каждый день** отдельно (в рамках одного дня — одна карточка,
   другой день — новая карточка), как и было в текущей структуре по дням.
3. Каждая операция — отдельная строка с тонким светло-серым разделителем,
   который начинается **после левой аватарки** (не под ней), с комфортными
   вертикальными отступами уровня стандартных списков iOS.
4. Слева в строке — сохранённая текущая аватарка (эмодзи категории/счёта,
   без изменения логики выбора).
5. По центру — название операции (категория `+` подкатегория) полужирным
   тёмным текстом; всё «остальное» (заметка/note, значок чека) — отдельной
   строкой **ниже** названия, серым мелким текстом.
6. Справа — сумма; **над суммой** — мелким серым текстом счёт операции со
   своей аватаркой (эмодзи счёта).
7. Цвет суммы: расходы — спокойный красный (`var(--expense)`), доходы —
   спокойный зелёный (`var(--income)`), переводы — нейтральный
   (`var(--muted)`).
8. Никаких ярких градиентов, тяжёлых теней, цветной заливки на всю строку
   или толстых рамок — только фон карточки белый, тонкая линия-разделитель,
   без заливки строки цветом категории (текущая реализация заливает всю
   строку `background:${c.color}14` — это убрать для Главной).
9. Сохранить все данные, сортировку, обработчики нажатия/редактирования,
   фильтрацию и расчёты без изменений — только разметка и стили.

## Критерии готовности

  жирным тёмным, счёт мелким серым с эмодзи над суммой, сумма

    для расходов, зелёная (`var(--income)`) для доходов, нейтральная

    (`background:${c.color}14`/`var(--accent-soft)` на всю `.tx`) — фон
