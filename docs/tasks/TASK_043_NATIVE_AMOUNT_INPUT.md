# TASK_043 — Ввод суммы через системную клавиатуру iOS (нативное поле)

**Статус:** DONE (локально, commit без push — по требованию постановки;
ощущение отклика системной клавиатуры — на реальном iPhone пользователя)

## Контекст

`TASK_042` подтвердила: в PWA на iPhone настоящий haptic на собственных
HTML-кнопках недоступен (полевая проверка на iOS 26.6.2 — отклика нет).
Системная цифровая клавиатура iOS даёт тактильный отклик сама — при включённой
настройке «Настройки → Звуки и тактильные сигналы → Отклик клавиатуры →
Тактильные сигналы». Приложение не обещает и не имитирует вибрацию.

## Анализ текущей реализации

- Сумма — статический `.display > #dispMain` (текст, `role=button`), тап
  открывает кастомный циферблат `#keypadDock` (`openKeypad`), ввод — через
  `key(k)` → `applyKey` → строка выражения `aExpr` ('45.52', '12+3×2') →
  `evalExpr` → число. Перевод: две стороны `#tdFrom/#tdTo` с `transFocus`,
  зеркалирование/автоконвертация в `key()`/`syncTransTo()`.
- Сохранение (`saveTx`) читает только `evalExpr(aExpr)`/`evalExpr(aToExpr)` —
  модель данных от способа ввода не зависит.

## UX-варианты

- **A (выбран).** Нативное поле `<input inputmode="decimal">` — основной ввод;
  калькулятор — дополнительный режим (кнопка «Калькулятор» под суммой и в
  панели над системной клавиатурой). Обе стороны перевода — тоже нативные поля.
- B. Только нативное поле, калькулятор удалить — теряется арифметика
  (`12+3×2`, зеркалирование/конвертация в переводах), которая работает и
  покрыта кодом; удаление не обосновано.
- C. Калькулятор первым, нативное поле по долгому тапу — не решает задачу.

## Границы работы

Разрешено: разметка/CSS/обработчики блока суммы и карточки перевода в
`index.html`; новая панель «Готово/Калькулятор» над системной клавиатурой;
новый сервис `js/services/amount_input_service.js` (чистые правила ввода);
`sw.js` (precache + версия); тесты; документация.

Запрещено: Capacitor/Xcode/нативные зависимости/платные сервисы;
`navigator.vibrate`/switch-хитрости для haptics (сервис `Haptics` из
`TASK_042` не расширяется; клавиши калькулятора его вызывают как раньше —
на iPhone это no-op); изменение `applyKey`/`evalExpr`/`saveTx`/модели
данных/экспорта/импорта/аналитики; push/deploy.

## Требования

1. Тап по сумме → фокус настоящего `<input type="text" inputmode="decimal"
   enterkeyhint="done">` → системная клавиатура iPhone.
2. Правила ввода: запятая — основной разделитель, точка принимается и
   заменяется; одна запятая; ≤ 2 знака после запятой; промежуточное `45,`
   допустимо; при завершении `45,5 → 45,50`, `45, → 45`, `,5 → 0,50`,
   пусто → `0`; никаких `NaN`; `aExpr` всегда каноническая строка ('45.52').
3. Новая операция: при фокусе значение `0` очищается (плейсхолдер `0`) —
   ввод `45,52` сразу, без стирания.
4. Завершение: собственная компактная панель над клавиатурой
   («Калькулятор» · «Готово»), позиционируется по `visualViewport`;
   Enter на аппаратной клавиатуре = «Готово»; по «Готово» — нормализация,
   закрытие клавиатуры, форма готова к выбору категории и сохранению.
5. Дизайн формы, цвета, иерархия сохранены; знак — отдельный span (как в
   `TASK_014`), валюта — отдельный span справа, не мешает редактированию.
6. Калькулятор — режим: открывается кнопкой; его результат пишется в поле.
7. Умеренный pressed-state для оставшихся кастомных кнопок с учётом
   `prefers-reduced-motion`; не выдаётся за haptic.

## Критерии готовности / план проверок

- Юнит-тесты сервиса (sanitize/toExpr/normalize/fromNumber) + статика.
- Regression suite без падений.
- Preview 320/390/430: `45,52`, `0,50`, `100`, `100,5`, `45.`/`45,`,
  удаление/очистка/повторный ввод, расход/доход/перевод, «Готово»,
  калькулятор `12+3×2` → поле `18`, сохранение, редактирование старой операции.

## Результат (фактически)

### Выбранный вариант — A

Нативное поле — основной ввод; калькулятор сохранён как дополнительный режим.
Причина: арифметика (`12+3×2`, зеркалирование и автоконвертация в переводах)
реализована и работает, удалять её без запроса нет оснований; при этом она не
должна быть обязательным первым экраном — теперь открывается кнопкой.

### Что изменилось в процессе ввода суммы

- Блок суммы `#dispMain` = `[знак][<input id="amtInput" type="text"
  inputmode="decimal" enterkeyhint="done">][валюта]`. Тап по сумме → фокус
  поля → системная цифровая клавиатура iPhone с разделителем. Ширина поля
  подбирается по скрытому измерителю `.amt-measure`, валюта стоит вплотную и
  не мешает редактированию; `fitAmount()` учитывает поле.
- При фокусе `0` (и разрядные пробелы) убираются — ввод `45,52` начинается
  сразу; плейсхолдер `0`. Подчёркивание поля в фокусе — подсказка
  редактируемости; при нулевой сумме — подпись «Введите сумму».
- Правила ввода — новый чистый сервис `js/services/amount_input_service.js`
  (`AF.Services.AmountInput`): `sanitize` (запятая основной разделитель, точка
  принимается, одна запятая, ≤ 2 знака, ведущие нули), `toExpr` (каноническая
  строка для `aExpr`, без NaN), `normalize` («Готово»: `45,5 → 45,50`,
  `45, → 45`, `,5 → 0,50`, пусто → `0`, целые без `,00`), `fromNumber`/
  `display` (загрузка сохранённой операции; вне фокуса — с разрядными группами
  `12 500,50`, в фокусе — `12500,50`).
- Модель не менялась: поле пишет в `aExpr`/`aToExpr` каноническую строку;
  `evalExpr`/`saveTx`/`updateSaveEnabled` работают как раньше. В фокусе поле не
  перезаписывается `updateDisplay()` (`amtPaint`).
- Перевод: обе стороны `#amtFrom`/`#amtTo` — такие же поля; фокус задаёт
  `transFocus`, ввод «Со счёта» зеркалится/конвертируется через существующий
  `syncTransTo()`; `saveTx` при отсутствующей сумме зачисления фокусирует
  `#amtTo` вместо открытия калькулятора.
- Завершение: панель `#amtBar` («Калькулятор» · «Готово») над системной
  клавиатурой, позиция — по `visualViewport` (`placeAmtBar`); футер с основной
  кнопкой уезжает на время ввода (`.sheet.amt-open`, как при калькуляторе);
  `pointerdown.preventDefault` на кнопках панели — поле не теряет фокус до
  `click`; Enter на аппаратной клавиатуре = «Готово». По «Готово» — normalize,
  blur, панель скрывается, форма готова к категории/сохранению.
- Знак (`−`/`+`) — отдельный `#dispSign` по типу операции (семантика
  `TASK_014` сохранена: знак не входит в значение).

### Что стало с калькулятором

Сохранён полностью (`#keypadDock`, `key()`/`applyKey`/`evalExpr`, `✓`,
«Готово» циферблата, `TASK_042`-обработчики). Открывается кнопкой
«Калькулятор» под суммой (`#calcPill`) или из панели над системной
клавиатурой; при фокусе поля закрывается (вместе не показываются). Результат
выражения пишется в поле (`12+3×2` → `18`).

### Тактильный отклик

Обеспечивается iPhone для системной клавиатуры при включённой настройке
«Настройки → Звуки и тактильные сигналы → Отклик клавиатуры → Тактильные
сигналы». Приложение вибрацию не вызывает и не имитирует; `navigator.vibrate`,
switch-хитрости в новом коде отсутствуют (проверено тестом). Pressed-state
кнопок — только визуальный, с `prefers-reduced-motion`.

3. Программно (события `focus`/`input`/`blur`): `45,52`, `0,50` → `0,50`,

   знак `+`, `amount: 0.5`; перевод `100,5` → обе стороны `100,50`,

4. Ширины 320×690, 390×844, 430×932: `documentElement.scrollWidth` = ширине
   вьюпорта (нет горизонтального overflow), `fitAmount` ужимает `−12500,5`
   на 320, стороны перевода `−1234,5 € › +1 234,50 €` помещаются, калькулятор
   как режим. Консоль — только известный CORS-шум `cloudflareinsights`.
5. Реальный iPhone в сессии недоступен: поведение системной клавиатуры
   (`inputmode=decimal`, позиция панели над клавиатурой по `visualViewport`,
   тактильный отклик) — на проверку пользователю.

### Известные ограничения

- Позиция панели над клавиатурой рассчитана на оба поведения iOS (сжатие
  layout-viewport в standalone / только visual-viewport в Safari) — требует
  подтверждения на устройстве.
- Тип ввода `type="text"` (а не `number`): iOS с `number` не даёт запятую и
  ломает `45,52`; валидацию полностью берёт на себя `sanitize`.
- В калькуляторе тактильного отклика на iPhone по-прежнему нет (`TASK_042`).
