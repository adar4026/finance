    (нормализованный подбор счетов и категорий + словарь двуязычных синонимов:
    `Groceries` → существующая «Продукты», а не двадцать первая копия),
    `import_service` (операции, отпечатки-дубликаты, валидация, `apply()`,
    `undo()`) и `xlsx_writer_service` (настоящий `.xlsx` — ZIP со store и CRC32
    плюс OOXML, вместо HTML-таблицы с расширением `.xls`; даты датами, суммы
    числами, поэтому в файле сразу работают сортировка, фильтр и суммирование).
    Мастер импорта состоит из четырёх шагов — анализ файла → сопоставление
    (колонки, счета, категории) → предпросмотр → результат, — и **до кнопки
    последнего шага база не меняется ни на одну запись**; это проверяется
    конструктивно: ни один шаг, кроме `impCommit()`, не обращается ни к
    `AF.Store.save()`, ни к `state.*.push`. Атомарность построена на примитиве
    из `TASK_026`: `Import.apply()` работает с клоном и возвращает новое
    состояние, запись — единственный `AF.Store.save()`, при отказе результат
    просто выбрасывается. Дубликаты определяются мультимножеством отпечатков
    (дата, тип, сумма, валюта, счёт, категория, контрагент, а для перевода —
    счёт-получатель), поэтому повторный импорт даёт ноль новых операций, но два
    одинаковых кофе в один день импортируются оба. Резервная копия получила
    явный конверт (`format`, `backupVersion`, `schemaVersion`, `appVersion`,
    `createdAt`, `counts`, `checksum` FNV-1a по канонической сериализации) и
    функцию `inspect()`, которая **читает и показывает**, ничего не восстанавливая;
    старые копии `{app,data}` и «голый» state читаются по-прежнему. Восстановление
    идёт строго по шагам: предпросмотр → автоматическая safety-копия файлом →
    миграция → запись → **перечитывание из хранилища и сверка счётчиков** → и
    только потом успех; при несошедшейся сверке прежняя база возвращается из
    `AF.Store.snapshot()`. Реализована отмена импорта (`importBatchId` на
    созданных сущностях + журнал `state.importBatches`), причём счёт или
    категория, на которые успела сослаться собственная операция пользователя,
    при отмене сохраняются. `alert()`/`confirm()` на путях импорта и
    восстановления нет — только существующие тосты и экраны предпросмотра.
    `SCHEMA_VERSION` намеренно **не** поднимался: `importBatches` — необязательный
