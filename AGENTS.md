# AGENTS.md — рабочий процесс A-Lex Finance

Этот файл фиксирует обязательный порядок работы над проектом A-Lex Finance
по принципу TASK-системы (аналогично проекту Ministry).

## 1. В начале каждой новой рабочей сессии прочитать

1. `AGENTS.md` (этот файл).
2. `CLAUDE.md`.
3. [`docs/PROJECT_BASELINE.md`](docs/PROJECT_BASELINE.md).
4. [`docs/PROJECT_STATUS.md`](docs/PROJECT_STATUS.md).
5. [`docs/ROADMAP.md`](docs/ROADMAP.md).
6. Файл текущей активной задачи из `docs/tasks/`.

## 2. Перед изменением кода

Обязательно создать отдельный файл задачи:

```
docs/tasks/TASK_XXX_SHORT_NAME.md
```

## 3. Статусы задач

- `PLANNED`
- `IN PROGRESS`
- `BLOCKED`
- `DONE`

## 4. Правила ведения задач

- Одновременно может выполняться только **одна** основная задача.
- До начала реализации задача должна содержать:
  - цель;
  - границы работы;
  - требования;
  - критерии готовности;
  - список того, что изменять запрещено;
  - план проверок.
- Перед изменением кода — перевести задачу в статус `IN PROGRESS`.
- После реализации записать в TASK-файл:
  - что планировалось;
  - что фактически реализовано;
  - какие файлы изменены;
  - какие проверки выполнены;
  - известные ограничения;
  - связанные Git-коммиты;
  - статус публикации, если выполнялся деплой.
- Только после успешных проверок менять статус на `DONE`.
- После завершения задачи обязательно обновлять:
  - `docs/PROJECT_STATUS.md`;
  - `docs/ROADMAP.md`;
  - `CHANGELOG.md`, если изменение относится к истории версии.
- Следующую задачу нельзя начинать, пока предыдущая не закрыта фактической
  записью в соответствующем TASK-файле.

## 5. Формат коммитов

- Коммит реализации: `feat(TASK_XXX): краткое описание`
- Коммит документации: `docs(TASK_XXX): краткое описание`

## 6. Роль `PROJECT_BASELINE.md`

`docs/PROJECT_BASELINE.md` описывает состояние, существовавшее **до**
внедрения TASK-системы. Его следует обновлять только при осознанном
изменении базового описания архитектуры, а не после каждой небольшой задачи.

## 7. Границы

- Не изменять код, интерфейс, зависимости или бизнес-логику за пределами
  активной задачи.
- Не смешивать несколько независимых этапов в одной задаче или одном коммите.
- `CHANGELOG.md` используется для краткой истории версий и не заменяет
  подробные TASK-файлы.
